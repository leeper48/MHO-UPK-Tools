What the app does

MHO Package Modifier reads and changes Marvel Heroes Omega's game packages (.upk files in the game's CookedPCConsole folder). With it you can:

  • look inside any package: every object, its class, size and properties;
  • change numbers and colours (fog, sun, sky, material parameters), in one package or in every package that has the same object;
  • export meshes to FBX with their textures, edit them in Blender and import them back;
  • edit the buildings of a whole zone in Blender: add missing walls, move, rotate, scale, reshape or delete pieces;
  • replace a texture with your own image, or add new textures, and build materials that use them;
  • copy materials, meshes and other objects from one package to another;
  • rebuild a zone's distant view (sky, far-away buildings, ground, water) with one click;
  • undo any change, or put a package back to its original.

The Start tab lists these tasks; each card takes you to the right tab. The log at the bottom of the window shows everything the app does, including what each check found.

How your game files stay safe

  1. Close the game before writing. The game keeps its packages open, and it only reads a changed package when it starts. The top right of the window shows whether the game is running. While it is, the app blocks every write and tells you.
  2. Check first. Every change has a Check (dry run) button. It builds the new package and verifies it exactly like the real write, but saves the result in import_out next to the app instead of the game folder. Read the log: it says what would change.
  3. The original is kept. The first time the app changes a package, it copies the package to <package>.upk.bak and checks the copy byte by byte. The app never changes or deletes a .bak.
  4. Every write is verified. The new package is written to a temporary file, read back and checked, and only then does it replace the game file.
  5. Everything can be undone. Each write is one step in the package's history (the last 20 steps are kept). Undo on the Backups tab (Ctrl+Z) steps back one write, Redo steps forward, and Revert to original copies the .bak back.
  6. Your work files are never overwritten. Files the app exports go into the export folder. If a file with that name already exists, the app uses a new name (_2, _3, ...) instead.
Changes stack: each change is built from the current game file, so a later change keeps the earlier ones. The exceptions are zone rebuilds, which start from the original every time, and re-importing an updated placements file, which replaces the earlier import of that same file.

Getting started

  1. Game folder. On its first start the app looks for the game in your Steam libraries. If it isn't found, set Game folder at the top to the game's CookedPCConsole folder, e.g. ...\Marvel Heroes\UnrealEngine3\MarvelGame\CookedPCConsole. Browse… picks it; Reload list re-reads it.
  2. Export folder. On the Meshes tab, choose where the app should put the files it exports (FBX, textures). This is also a good place for your own work: keep each job in its own subfolder.
  3. Open a package. Type part of a package name in Package (it suggests matches), then Open or Enter. Open file… opens a package from anywhere on disk.
  4. Look and theme. Light mode / Dark mode switches the colours; the app remembers your folders and choices.

Everything the app can do is also available from the command line (see Command reference); running the exe without arguments opens this window.

Updates

The app checks for a new version when it starts, at most once a day (turn it off on the Start tab, or click Check for updates there). When one is out, a link appears at the top right of the window: Yes downloads it, checks its checksum (a damaged or altered download is refused), installs it over the app folder and restarts; No opens its release page. Only the app's own files are replaced: your settings, undo history, exports and anything else in the folder stay. Keep the app in a folder you can write to (not Program Files).

Command line: --check-update, --update, or --install-zip <zip> for a release zip downloaded by hand (with its .sha256 next to it).

Task: change a value (fog, colours, material parameters)

  1. Open the package (for zone fog and sky: the zone's main level, e.g. MidTown_Static.upk).
  2. On Browse, type a filter (e.g. fog) and double-click the object. It opens on the Properties tab.
  3. Edit values in the Value column. Numbers are typed; colours can be picked by double-clicking the row. For a material instance, its parameters are the param:<name> rows. Changed rows are highlighted; ↺ puts the original (.bak) value back into the box.
  4. Optional: Find matching packages lists every other package with this same object and its current values. Tick the ones that should get the same change (packages with the same name prefix are ticked for you).
  5. Dry run, read the log, then Apply to game file(s)….

Only values the package already stores can be changed; a value left at its default isn't stored and doesn't appear. Colours are entered as R,G,B[,A].

Task: replace a mesh with your own model

  1. Open the package that contains the mesh. If the mesh isn't in the list, the package only refers to it: on Browse, Where does this mesh come from? shows which package holds it.
  2. On Meshes, select it and Export selected mesh to FBX. The FBX and its textures go to the export folder.
  3. Edit it in Blender. Keep the object names (<mesh>_section<N>) and the material names: each material becomes a section of the mesh again (Blender's .001 suffixes are ignored). The file has no custom normals; Blender's own are fine.
  4. Export it as FBX, choose it in FBX to import, Dry run import, then Import into game file….
A mesh can have at most 65,535 vertices. The imported mesh has no collision. Imported meshes are used everywhere the original is: to change just one placed building, use Placements instead.

Task: edit a zone's buildings in Blender (Placements tab)

Add missing walls, move, rotate, scale, reshape or delete the placed meshes of a tiled zone (Hightown, Odin's Palace, or your own layout). The work goes in three steps.

1. Export the zone for Blender

  1. Pick the Zone. The tile layout, region library and offset are filled in (choose Custom to give your own).
  2. Check FBX to write. By default it goes to <export folder>\<Zone>_placements\.
  3. Filters: Smallest footprint / Smallest height leave out small pieces (64 / 0 keeps thin pieces such as awnings); Skip meshes / Skip materials leave out anything whose name contains one of the words.
  4. Export for Blender. You get the FBX (one object per placed piece, named T<tile>_E<number>_<mesh>, with one child object per material section), its textures, and a <name>_placements.txt file. Keep that file: the import needs it. Explorer opens at the FBX.

2. Edit in Blender

To…Do this
Add a pieceSelect the piece with its children (right-click, Select Hierarchy), Shift+D, move it. The copy is named like the original plus .001.
Move, rotate or scale a pieceIn Object Mode, on the piece itself (the parent object).
Reshape a pieceEdit Mode on its section objects (..._s0, ..._s1): extend a wall, copy windows, delete faces. You can also duplicate, move or mirror section objects, as long as they stay under the piece.
Delete a pieceDelete it with its children, and tick Remove originals I deleted in Blender when importing.
Don't rename objects, don't join pieces together, and don't apply transforms (Ctrl+A) to the pieces. Leave the untouched pieces in the file: the app uses them to work out how Blender placed everything. Export the whole scene as FBX with Blender's default settings, under a new name in the same folder (Blender's + file number is handy).

3. Bring your edits into the game

  1. Placements file is filled in after an export; otherwise choose the _placements.txt.
  2. Edited FBX: your file. Newest in folder picks the most recent FBX there that isn't an export of the app.
  3. Keep Keep baked lighting ticked: new pieces then glow like their originals. Without it they come out dark.
  4. Check (dry run). The log lists every change, for example:
    add  T51_E167_..._wall_a.001: in-game (18455, -1432, 6) ... edited mesh -> HighTown_X6_Y6_B_NESW_B.upk
    move T51_E167_..._wall_a: ...
    mesh T51_E207_..._shops_e_corner: edited geometry, placement unchanged
       parts moved or copied in Blender: ..._s0.002, ..._s0.003 (mirrored: faces turned outward)
    and ends with verify: PASS for each tile.
  5. Write to game… (with the game closed). Each changed tile is written once and verified.

Changing it again

Keep working in the same Blender file and import the whole file again. The app sees that this placements file was imported before and starts each tile from its version before that import, so nothing is added twice and a piece you took out again disappears. You don't need to undo first.

What happens to your edits

  • Copies become new placed pieces, with the original's mesh, materials and lighting.
  • Moved originals get their new position, rotation and scale, and keep their own lighting.
  • Reshaped pieces get their own copy of the mesh in their tile (named <mesh>_<tile>_e<N>), rebuilt from your geometry. Each face takes its lighting coordinates and normals from the original face it was copied from, so copied windows light like the originals. Mirrored parts are turned the right way out.
  • Deleted originals are removed from their tile's list (only with Remove originals I deleted). The app refuses if more than half the pieces are missing: that looks like a partial export.
Limits: reshaped pieces have no collision (walking is decided by the server anyway). A few pieces are placed by their own actor instead of the tile's list; moving, reshaping or deleting those is skipped and reported. The round trip works for tiled zones only. Self-test checks the maths on your export without changing anything.

Task: replace a texture, or add a new one

On Textures, Import an image works two ways:

  • Replace the selected texture: the texture you select in the list gets your image. It keeps its name and path, so every material that uses it shows the new image, with nothing else to change. All its other settings (texture group, sRGB, normal-map compression, clamping) stay as they were.
  • Add as a new texture: a new texture next to the selected one, which serves as the template (a diffuse for a diffuse, a normal map for a normal map); the new one copies its settings. Give it a New name (no spaces or dots). It isn't used by anything until you make a material that uses it.
  1. Open the package that holds the texture (to add one: the package whose material will use it).
  2. Select the texture in the list: the viewer shows it, so you can check it's the right one. Choose the mode.
  3. Choose the Image (PNG, JPG, BMP or DDS). Preview shows it in the viewer.
  4. Compression: Automatic picks DXT1 for opaque images and cut-outs, DXT5 when the image has soft transparency. Alpha cut-off (DXT1 only) keeps pixels whose alpha is above it (85 matches the game's masked materials). Brightness scales the colour. Largest size shrinks big images (512 is plenty for distant LODs). No mipmaps only for things always seen at one distance, such as a sky: without mipmaps, distant surfaces shimmer.
  5. Check (dry run), then Import into game file…. After a replace, the viewer shows the texture with its new image.
Stock textures keep their large sizes in the game's .tfc texture caches. A replaced texture stores all its sizes inside the package instead (the way other mod tools do it), so the package grows. The same texture can also exist in several packages (same path); the game uses the copy it loads first. If your replacement doesn't show, Find name in folder (Browse tab) lists the other packages that have it: replace it there too.

Task: make your own material

The game can't compile new shaders: every material must match one it already has. So you copy an existing material instance that has the features you need and swap its textures and values.

  1. Find one. On Objects, Find a material with the features you need: give part of the parent material's name and the switches, e.g. useemissive=true. Translucent, masked and emissive looks come from the parent.
  2. Copy it. In Copy an object into another package: the source package and the material's path, the target package, and a New name (always rename a copy you'll change, see the warning below). In Replace references, point its textures at yours, one per line: original.texture.path=your.texture.path. What would be copied? lists everything the copy brings along. Leave out physmaterial if it can't be copied (it only carries footstep sounds).
  3. Use it. Point a placed mesh's material at the copy: Tools, --set-object (e.g. Materials[0]).
  4. Tune it. Its colour and number parameters are param: rows on the Properties tab.
Objects are known by their path. A copy with the same path as an object in another package replaces that object for everything loaded after it. A broken copy of the water material once broke all water in a zone. Rename copies. Never leave out materialfunctioninfos: the material then renders as the default checker pattern.

Task: rebuild a zone's distant view (Zones tab)

Some zones show a void or a flat colour past their edge. A zone build rebuilds the zone's main level from its original with a whole recipe: sky, distant buildings (grey boxes or baked LODs, hidden near the camera so the real ones show up close), ground and water planes, fog. The recipes for Hightown, Industry City and Odin's Palace come with the app (their input files are in the ZoneData folder next to it).

  1. Select the zone; its description says what the recipe does.
  2. Walls: the zone's facade texture or plain grey (where the zone has a facade). LOD textures: the largest size for distant textures (512 keeps the package small; Original keeps them as supplied).
  3. Dry run, then Build and write to game…. The whole rebuild is one undo step.
A rebuild always starts from the original main level, so it replaces an earlier build. Changes to other packages (tiles, libraries) aren't touched by it.

Task: bake LODs or a ground plane (Zones tab)

Export placed meshes for baking in Blender writes a zone's real placed meshes, in their in-game positions, with materials and textures, as one scene:

  • Buildings (for LODs) keeps structures and containers (100+ high, 100+ across) and skips fences, trees, poles and cables. Bake them in Blender into a low-poly mesh with a texture atlas.
  • Flat ground (for a ground bake) keeps the ground (at most 16 high) without water. Bake it top-down onto one textured plane.

The zone recipes take such baked files from ZoneData\<Zone> (e.g. lod_bundle1.fbx + lod_bundle1_diff.dds). Replacing a recipe's input means replacing the file there and rebuilding the app, so ask the tool's maintainer.

Tab: Properties

The values the selected object stores. Columns: Value (editable), Current in file, Original (.bak) and ↺ (put the original value back). Numbers, colours and material parameters can be changed; greyed rows are shown for information. See Task: change a value.

Also apply to: Find matching packages scans the game folder for the same object in other packages and lists their values; tick the ones that should get the change. Dry run checks every ticked package; Apply to game file(s)… writes them all. Reset edits discards changes you haven't applied yet.

Tab: Meshes

The open package's StaticMeshes on the left, the selected one in 3D on the right. Export to FBX (+ textures), UV info (texture coordinate ranges per section), Round-trip self-test (exports and re-imports the mesh in memory and compares: a quick check that a mesh can be edited). 3D view

Click a mesh in the list and it shows on the right in 3D, with its textures when the package has them (each section's material is followed to its colour texture, from the package or the .tfc caches; the log says how many sections got one). Meshes cooked into map tiles carry no materials of their own (the placed piece supplies them): their sections show in plain colours.

To…Do this

  • Wireframe: the triangle edges over the surface.
  • Backfaces: the game draws only the front of each face. Ticked, back sides are drawn red, so a face turned the wrong way (for example a mirrored copy, or a wall seen from inside) stands out.

Texture viewer

Click a texture in the list and it shows on the right (you can move through the list with the arrow keys). The viewer shows the largest version of the texture the game has (from the package, or the bigger one in the .tfc caches). Many stock textures only keep smaller sizes: the status line says when the full size isn't stored anywhere.

  • Show: Colour with alpha over a checkerboard (transparent parts show the squares), Colour only, Alpha only (white = opaque), or one channel (Red, Green, Blue), which is useful for packed textures such as a spec map whose green channel is the glow.
  • Zoom: Fit to the window, or 25–800% (Ctrl+mouse wheel). Zoomed in, pixels stay sharp.
  • The pixel under the mouse is shown with its R, G, B and A values.
  • Save as PNG… writes the texture, with its alpha, at full resolution.
  • Pop out opens the same image in its own window (e.g. on a second screen); you can open several.

Formats shown: DXT1, DXT3, DXT5, BC5 and V8U8 normal maps (their third axis is rebuilt so they look like normal maps), 32-bit colour and greyscale.

Tab: Tools

Every command of the app, grouped, including those without a tab of their own (sky domes, component copies, level actors, diagnostics). Pick one: its syntax, what it does and an example appear. The example is filled in with the open package, the object selected on Browse and your export folder. Edit the Arguments, then Run. Commands that write keep Dry run ticked until you untick it, and ask before writing. Copy as command line copies the full command, for scripts. Words in <angle brackets> are yours to fill in.

Command reference

Run MHO_UPK_Mod.exe <command> <arguments> from a command prompt, or use the Tools tab. Commands marked writes change the game file only without --dry-run, with the same safety steps as the tabs. Put paths with spaces in quotes.

Troubleshooting

What you seeWhy, and what to do
"The game is running" and nothing is writtenClose the game (the header turns green), then write again.
A change doesn't show in the gameThe game reads packages when it starts: restart it. Check the Backups tab: is the package "MODIFIED"?
New pieces look darkThey were imported without their lighting: import again with Keep baked lighting ticked.
A new or reshaped piece is invisible from one sideGame faces are one-sided. A face pointing into the building can only be seen from inside. Turn the piece (or flip the faces) in Blender and import again.
A piece I copied in Blender didn't appearCheck the import log. A copy must keep the original's name plus .001. A copied section object must stay under its piece, or it's listed as matching nothing. Objects that were renamed or joined are ignored.
"the originals don't agree on one conversion"Too many untouched pieces were moved, or the file was exported with transforms applied. Export the whole scene with default settings.
A material shows a checker patternThe material couldn't find something it needs: often a reference to a package the game hasn't loaded at that point, or a copied material with materialfunctioninfos left out.
Streaky or swirly lighting on reshaped facesFixed in 2.44.1: faces now take their lighting from the face they were copied from. Faces with new texture coordinates use the nearest original vertex and can look slightly off.
The game crashes in tbbmalloc.dllAn occasional crash in some zones, which also happens without mods. Start the game again. If it keeps crashing at the same place right after a change, Undo that package and report it.
"Undo refused: the live file isn't the version after the last recorded change"Something else changed the package since the app's last write (another tool, or a copy). Use Revert to original, or run --undo ... --force from Tools if you're sure.
