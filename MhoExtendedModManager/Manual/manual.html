MHO Extended Mod Manager

Manual for version . Press F1 in the app to open it, Ctrl+F here to search.

MHO Extended Mod Manager installs, orders and removes mods for Marvel Heroes Omega. It reads and writes the same mod format as MHModManager 1.0.1, so mods made for either work in both, and it adds a lot on top: Borrow Power (give a hero's power another hero's power look), a 3D preview, an editor with an icon creator, Nexus update checks, and moving a costume mod to another costume.

Getting Started

  1. Install. Run the Setup file (or unzip the ZIP) anywhere except Program Files or the game folder: the app keeps everything in a data folder next to itself. It needs the .NET 8 Desktop Runtime; Setup offers Microsoft's download if it's missing.
  2. Windows may warn you. The app isn't code-signed, so SmartScreen can say "Windows protected your PC": click More info, then Run anyway. Download it only from Nexus or the GitHub releases page, and compare the .sha256 file if you want to be sure.
  3. First start. The app finds the game through Steam (or asks you to browse to it), then asks whether you used MHModManager. If you did, it copies your mods, their order and on/off state, and the verified stock backups; your old folder isn't changed. Stop using the old manager afterwards, or the two will undo each other's changes.
  4. Use it. Tick the mods you want, order them, and press Apply Changes with the game closed.
Everything the app keeps (your library, settings, the record of what it wrote to the game, 3D views) is in data next to the exe. Keep one copy of the app: a copy somewhere else has its own data.

Install a Mod and Put It in the Game

  1. Download the mod (a .zip, .7z or .rar). Close the game.
  2. Click Install Mod (the download arrow at the top left), or drag the archive onto the window. The mod appears at the top of the list, turned off. (Mods for the older MH Texture Manager, a .json and a .tfc, are converted into ordinary mods as they're installed.) A game package on its own (a .upk, or an archive or folder of them with no manifest.json) becomes a mod named after it; only the game's own package names are taken.
  3. Tick its checkbox. The status line at the bottom now says how many game files will change.
  4. Click Apply Changes at the bottom right (or press Ctrl+Enter). A window lists what will be written; click Apply. When it closes, the mod is in the game. Tick Don't Ask Again beside the buttons to skip this window from then on: Apply Changes writes right away and the status line says how it went. If the checks found something, the status line says so; click it to open the window with the details. Only an apply that stops shows a window. Settings → Ask Before Applying (or unticking the box) turns the window back on.
  5. To take it out again: untick it and Apply Changes. The game's original files go back.

Rebuild a Mod After Updating the Mod Manager

A new version of the Mod Manager can build a mod's files better (a fix to power colors, for example). Mods you made before keep their old files until they're built again.

  1. On the Mods tab, right-click the mod's card → Resave. It builds the mod again with this version and saves it, in a few seconds and without opening the Editor (the same as Edit, then Save).
  2. If the mod is on, click Apply Changes to put the rebuilt files in the game.

A mod with dodge ghosts or added props still needs Edit, then Save; Resave says so.

Remove Several Mods at Once

  1. On the Mods tab, mark the mods: Ctrl+click each one, or click the first and Shift+click the last.
  2. Click Remove Mod (the bin) or press Del.
  3. Read the warning: it lists every mod that will be removed, and Cancel is the default button, so Enter removes nothing. To keep one, Cancel and Ctrl+click it out of the selection.
  4. Click Remove N Mods. They're turned off, Apply Changes runs once, and their folders go to the discarded copies (a snapshot restore brings them back: Settings → Snapshots).

Decide Which Mod Wins

When two mods change the same file (two Storm costume mods for the same costume, say), the one higher in the list wins.

  1. Look for the colored stripe on a card's left edge: red means part of that mod loses to a higher one, amber means it only wins. Select the mod and open its Conflicts tab to see who wins what.
  2. To see every mod that shares files side by side, pick Group ▾ → Conflicts.
  3. Drag the card you want to win above the other (or select it and use ⤒ ▲ ▼ ⤓, or Ctrl+Up / Ctrl+Down).
  4. Apply Changes.

Keep a Mod's Look Near Other Players

  1. A mod with a yellow ⚠ OVERLAP pill changes a model the game also keeps in other files (a team-up's character is often also a summon or an NPC). Hover the pill to see which.
  2. Click OVERLAP (or right-click the card → Make Unique) and confirm.
  3. Apply Changes. The mod now keeps its look even when someone nearby loads the game's copy.

When sharing is what you want (a modded S.H.I.E.L.D. agent package that should also change Nick Fury's summoned agents, whose copy is in his own file): open the mod in the Editor, tick Keep Shared Paths on the right of Overview → Details, and save. The note under it says what each choice does; see Keep Shared Paths.

Group ▾ → Overlap lists every mod with an OVERLAP pill together. Group ▾ → Crash Risk does the same for the mods with a CRASH RISK pill. A model that only an enemy's power shares (a boss summoning a copy) counts too.

See OVERLAP.

Fix a Mod That Can Crash the Game

  1. A red ⚠ CRASH RISK pill on a card means a model in the mod can crash the game (an Array.h:575 error): it has more bones than another copy of the same model in the game (added bones for a cape, a dress, wings or a loincloth), or its mirror table doesn't have one entry per bone. Type is:crash in the filter to list every such mod.
  2. Click the pill. The window lists each finding and offers what fixes it: Make Unique (the mod's model gets a path of its own) and / or Fix Mirror Tables (every bone gets a mirror entry).
  3. Click the button. Only the mod's own package files change, saved like an edit; the pill goes away when nothing is left.
  4. Apply Changes. It's a good idea to let the mod's creator know too, so they can update it officially.

Models built on the Model tab are checked and fixed by Build into Mod and Save Changes. See CRASH RISK.

Mods that are fine alone can clash together. Apply Changes checks your turned-on mods as a set before it writes anything: under Checks it lists any model that would be in the game in copies with different bone counts (a crash risk), and any model two turned-on mods both changed (only one of them shows). Turn one of the mods off, or move the one you want above the other.

Find What Changed, and Go Back (Snapshots and Bundles)

  1. Settings → Snapshots. A snapshot is taken by itself every time the app starts and before every Apply Changes; Take Snapshot (the camera) takes one with a name of your own (say, before trying a new mod). Each is a few KB: which mods are on, their order, locks, tags and notes, each mod's version, install date and files (as a fingerprint), Make Unique and Keep Shared Paths, the OVERLAP and CRASH RISK warnings, what was done to it (installs, updates, Fix Mirror Tables and Make Unique for a Crash Risk …), and the game files Apply wrote.
  2. Compare with Now (the split square, or double-click a snapshot) lists everything that changed since: mods installed, removed, turned on or off, moved, updated, made unique, warnings that appeared, fixes done in between, game files written. Pick two and Compare Two for the changes between them. When the game worked yesterday and crashes today, that list is where to look first.
  3. Restore (the clock, beside the camera) puts a snapshot back after showing everything it changes: on/off, order, locks, tags and notes (mods installed since are turned off), and the mods' files as they were then. Every time a mod's folder is replaced (an edit, Make Unique, Fix Mirror Tables, an update, a bundle) or removed, the old folder is kept with the discarded copies, so Restore can bring back a removed mod, undo a fix or an update, and put Keep Shared Paths back. Without a kept copy, it still undoes Make Unique from the mod's own copy from before it, or just sets Keep Shared Paths back; anything else it can't bring back is listed. The mods' files at the moment you restore go to the discarded copies in turn, and a snapshot is taken first, so restoring that one takes it all back. Then Apply Changes.
  4. Discarded copies (the bottom row: how many and how big): kept 30 days by default (Keep Discarded: 7, 30 or 90 days, or until you clean them up) and deleted at a start after that. Copies a saved snapshot would still bring back are only deleted after a warning naming those snapshots and mods: Keep Them (asked again after as many days) or Delete Them. Clean Up Discarded (the boxed X) deletes them now, and can keep the ones snapshots need; the folder icon opens them (data\library\discarded).
  5. Make Bundle saves the mods themselves (every file) with their state in one .zip: to keep a set that works, or to move to another PC. It asks whether to take every installed mod or only the turned-on ones (the dropdown beside it can make that the default). Restore Bundle installs the bundle's mods your library lacks, replaces the ones that differ if you say so (yours go to the discarded copies), and puts the bundle's state back. A snapshot is taken first.

Reporting a crash: a Compare Two between the last snapshot that worked and the one that crashed, plus the mods it names, is the most useful thing to share.

Watch a Hero's Powers in the 3D Preview

  1. On the Mods tab, select a costume mod. The preview in the middle shows its model in 3D (click the 3D picture in the strip if it shows a picture).
  2. At the bottom of the preview, click one of the hero's power buttons. Its animation plays with the power's effects: beams reach toward a target in front of the hero at the height they aim, missiles fly there and burst where they land, and what a power does to the one it hits (a stun, a burn, an impact) plays there.
  3. Press P to pause. The Frame slider takes the focus, so the arrow keys step through the animation one frame at a time; P again plays on from there.
  4. Under the view, Chain (the link, beside Loop) plays a power's start, loop and end one after another, as the game plays them; right-click it for how many times the loop repeats. ◀ and ▶ beside the Frame slider step to the previous or next part; with Chain off they step through the animation list instead (from the last back to the first), each from its start. Right-click Head, Bust or Full Body (or Shift+click) to lock the camera to that part while the animation plays; do it again to unlock.
  5. Turn the effects off and on with Power FXs above the buttons. Click the power again to see all the hero's animations.
  6. An effect too faint to see? Open Look ▾ (the eye) and raise Effects (10 % by default; remembered for every 3D preview).
  7. Powers with effects but no animation (procs, passives, Doctor Doom's The Will of Doom) have buttons too: their effects play over the idle (with Power FXs on). A power that changes the character's materials for a moment (Doom's force field) shows it on the model.

See Preview.

See a Hero's Forms, Transforms and Summons

  1. Open the hero's mod in the Editor and go to Powers (or select the mod on the Mods tab and use the preview's power buttons).
  2. A form: pick the power that turns it on, or one of the form's own powers. Jean Grey's Unleash the Phoenix shows her Phoenix form: her flying animations, the flaming wings and the form's flames. The form's versions of her powers have buttons of their own, named after the form (Pyrokinetic Barrier (Unleash the Phoenix)). Another power takes the form off.
  3. A transform: Rogue's Final Form, Rocket Raccoon's Mechfall and Loki's Frost Giant show the transformed character, with its own animations and props, when the power that turns it on or one of its abilities is picked (Swift Claws (Final Form), Frost Orb (Frost Giant)).
  4. A summon: a power that summons a character shows it beside the hero for the power's length, with its own arrival animation and effects: Jean Grey's Telepathic Illusion (the costume's own illusion, see-through with the game's glow), Doctor Strange's Images of Ikonn, Nick Fury's agents, Squirrel Girl's squirrels. When the mod carries the summon's model, the mod's model shows, as in game. Full Body frames the summons too.

Known: Rocket's mech suit shows above its pilot in the preview. A summon stands beside the hero; in game it appears where the power is aimed. See Watch a Hero's Powers in the 3D Preview.

Make a Costume's Icons from the 3D Model

Every costume has a store image (300×420), a portrait (herohor, 180×136) and a costume icon (40×40). You can make all three from the costume's own model.

  1. Select the mod and click Edit Mod (the pencil at the bottom left). The Editor tab opens.
  2. Open Icons, then Store Images (or Icons for the portrait and costume icon). The list on the left shows the costume's own images first.
  3. Click the image to replace on the left, then the Create from 3D tab beside Replacements.
  4. Frame the character: drag to turn, right-drag to move, the mouse wheel to zoom. The framing buttons give the usual full body, bust or head shot. Pick a pose from the animation list and a frame with the slider; press O to lay the game's original over it to line things up.
  5. Click Take Snapshot, then Use as Replacement. (Save Large PNG ▾ saves a big copy for a post instead.)
  6. Click Save Changes (the check mark at the bottom right), turn the mod on and Apply Changes.

To use a picture you made elsewhere instead: on the Replacements tab, pick the image on the left and load your .png or .dds; it's converted to the right size and format. See Icons and Create from 3D.

Change a Costume's Name or Text

  1. Open the mod in the Editor and go to Strings.
  2. Type the current text (the costume's name, say) into Find Text or ID and click Search. The Used By column says what each result belongs to (a costume's name, a hero's, an item's), so you pick the right one.
  3. Select it and click Add Selected to the Mod ↓; it appears under This Mod's Changes. Type the new text in its replacement column.
  4. Save Changes, then Apply Changes.

Wear a Mod on Another Costume or Hero

A costume mod replaces one costume. Moving it gives you a copy on another costume, so you can wear both, or puts it on a different hero altogether.

  1. Select the mod. Its header shows Costume: … ▾; click it (or right-click the card → Move to Another Costume).
  2. Pick a costume of the same hero, Another Hero at the bottom of the list to choose a hero and then one of their costumes, or Team-Up to put the model on a team-up (Angel, Jessica Jones …): its icons, portrait and store image and the voice move too.
  3. The Move window shows what moves and what doesn't. Name in Game is the name the costume or team-up will show, ready to edit. Onto a team-up it suggests the costume's name made plain (ENHANCED Odin Costume becomes Odin). The line under it says whether anything else in the game shows that same name: if something does, renaming changes it there too. Untick it to keep the game's name.
  4. Click Create Mod. (A few costumes are a class of their own rather than their hero's, such as Captain America's American Dream. They're in the same list and move the way a move to another hero does: the costume's own package with your model put in.)
  5. The new mod "Name (on Costume)" is at the top of the list, turned on, with the original turned off. Apply Changes.

On another hero, the model and voice come along, while the target hero's animations and powers stay. See Move to Another Costume.

Turn a Costume into a Pet

Any costume or team-up mod can become one of the game's vanity pets: Iceman following you as Spider-Ham, Odin as Potted Groot. The pet stays a pet in the game (its item, its summon); only how it looks changes.

  1. Select the mod and click Costume: … ▾ in its header (or right-click the card → Move to Another Costume), then Pet.
  2. Pick a pet. Filter narrows the list; the line under the choices names other mods for that pet (the one higher in the list wins).
  3. Full Size (ticked) keeps the hero's size; unticked, the model takes the pet's own size (most pets are half size or less).
  4. Name in Game is the pet's name in the inventory, ready to edit: it suggests the costume's name. The line under it says whether anything else shows that name.
  5. Click Create Mod. The new mod "Name (on Pet …)" is at the top of the list, turned on (the original stays on: the costume and the pet use different packages). Apply Changes, then summon the pet in the game.

The pet takes the costume's model with its idle, run and fidgets; the costume icon becomes the pet's item icon and the hero portrait its store image. A pet mod can move on: right-click it → Move to Another Pet puts that pet on another one, whole (its own skeleton and animations, so Cosmo stays four-legged on Baby Groot). On the Editor's Model tab, the Pets tab does the same with any model: see Put a Model on an NPC, Enemy, Team-Up or Pet.

Recolor a Hero's Powers

  1. Open the mod in the Editor (a costume mod for that hero; save a new mod once first) and go to Powers.
  2. Pick a power in the bar of icons under the preview (hover one for its name; the view frames the whole character). Its animation shows in the preview; press ▶ to play it with its effects.
  3. Move Hue, Saturation and Brightness, or click one of the power's own colors under Colors in This Power to replace just that color (type a hex code, or use the color wheel and its eyedropper).
  4. Apply to All Powers gives the hero's other powers the same color. Save Changes, then Apply Changes.

A power that's missing from the list, or doesn't change fully in game? Add Package adds one of the game's effect packages under its file name; its color recolors the whole package, for every character that uses it (the preview doesn't show it: check it in game). See Add Package.

A power's colors change for every costume of that hero. See Power colors.

Make a Power Dark

  1. Open the mod in the Editor and go to Powers. Pick the power.
  2. Click Dark. It sets Saturation 0 %, Brightness 0 % and Opacity 500 %; move the sliders to fine-tune it (Opacity goes up to 1000 %: higher is more solid).
  3. Check the 3D preview: the effects show dark, as the game will draw them.
  4. Save Changes, then Apply Changes, and look at it in game.

What it changes: Translucent effects (energy fields, smoke) simply turn dark. Glows, beams and sparks that the game adds as light would vanish with a dark color, so Save redraws them with a copy of one of the game's translucent effect materials, keeping each effect's shape (beams keep their narrow core). Mesh effects and heat-haze distortion keep their own materials and can still fade.

See Dark powers.

Switch Off a Power's Sound, Effect or a Character's Hover

  1. Make a mod with one of the hero's packages (Packages tab → Add .UPK Files, from the game's CookedPCConsole folder: a costume, or the hero's own UC__MarvelPlayer_<Hero>_SF.upk), and save it once.
  2. Open it in the Editor and go to Powers. Pick a power, or <Hero>: Character (the Char tile) for the hero's own parts (hover, dodge, and the trails its animations draw, such as Magik's sword glow). Its Color tab recolors those parts' effects, such as the dodge's ghosts or the sword trails, as for a power. (The 3D view doesn't draw animation trails; check them in game. A trail's texture stored uncompressed keeps its own pixels, so the color tints it.)
  3. The Parts tab lists what it shows and plays: Settings (such as Can Transition to Hover), Attachments (props such as Invisible Woman's disc), Effects (▶ shows one in the 3D view over the idle: Dodge Effect shows the dodge's ghosts) and Sounds (▶ plays one). Untick the ones to switch off.
  4. A power's own effects play alone with ▶, on the character as the power shows it (Unleash the Phoenix: on her Phoenix form, with the wings). Pick the power again for all of them.
  5. Save Changes, then Apply Changes.

Change a Power's Mark on the Ground (Luke Cage's "CAGE")

  1. Make a mod with the power's package (Packages → Add .UPK Files: Cage Was Here is UC__PowerLukeCage_PunchTheGround_SF.upk), or open a mod that has the hero's costume, and go to Powers. Pick the power.
  2. On Parts, the power's marks on the ground are listed as Decal. Untick one to switch it off.
  3. Click ✎ beside it:
    • Decal Color: pick a color. The mark's glow and fade keep their own brightness. Game's Color puts the game's back.
    • For each of its images: Edit in <your image editor> opens it as a PNG in the program Windows uses for PNGs, such as GIMP. Each time you save it there, the 3D view shows the change. Replace uses an image file of your own, Export saves the game's image, and Back to the Game's Image forgets your change.
  4. Play the power in the 3D view. The mark is drawn the way the game blends it (a darker layer plus a glow in its color), with your changes.
  5. Save Changes, then Apply Changes. The images are kept in the mod's Decals folder and travel with it. Power Colors also tint a decal's glow and fade.

Dodge ghosts from your model: many heroes leave ghost copies of themselves when they dodge (54 of 66). The Dodge tile after Char in the power bar goes straight there (Parts, with the dodge playing; the hero's other own effects, such as level-up, get tiles of their own too). Parts shows Dodge Ghosts under the list: Make Them From This Model makes them from the mod's model, at the character's own size and where it stands: each in the hero's combat idle, leaning 10° another way (forward, back, left, right) to look like it's moving. Lean ▾ changes a ghost's lean, and the Lean slider how far they all lean (10° at first). To choose a ghost's pose, select it, pick an animation in the preview and drag Frame to the moment you want, then Use This Pose; Automatic takes that ghost back to its automatic pose. Show Pose (or a double-click on a row) takes the preview to a ghost's animation and frame. Exact Size, on the Ground (on) undoes the effect's own 1.1× size and 5-unit drop, so the ghosts stand on the ground at the character's size; Look ▾ → Ground shows the floor (a grid of hexagons, 50 units across) to check it. For a high-flying travel power (a flight, a sky ride), the floor sits where the game puts it, by the game's own rule: nothing until the power applies (its wind-up times its contact point: Hawkeye 0.26 s after activation, most flights 0.75 s), then it drops away in a straight line at the hero's climb speed (Hawkeye 170 units a second, Thor and Spider-Man 300, Green Goblin 140, Kitty Pryde 100, everyone else 600) to the flying height of 140, where it stays through the loop; it comes back at 600 a second during the end. The game plays the power's start animation over the wind-up (0.75 s), whatever its own length, then the loop, and the 3D view does the same (the Chain button beside Loop plays the start, the loop and the end one after another, to see the handovers; right-click it for how many times the loop plays, twice at first; pick any part to begin there; with Loop on the chain starts over, else it stops on the end's last frame; ◀ and ▶ on either side of the frame slider step to the previous or next part, from its first frame, playing or paused as it was, and go round: past the end back to the start); if the climb isn't finished by then (Hawkeye climbs slowly), the loop's first play continues it, so its first moments sit a little low, as in game. A ground animation borrowed onto a high-flying power has its start lowered by exactly the lift on that clock, so the hero stays on the floor through the wind-up. On the Animations tab, the Height panel under the 3D view puts a power's start, loop and end side by side on one strip, each as wide as it plays in game and each with its own height keys. The blue Feet line is the body's lowest point above the game's floor with the keys applied (the loop as its first play after the start): bring it to the middle line to put the feet on the floor. For a borrowed high-flying power the panel also has Climb Speed, how fast the game lifts the hero: his own from the game until you change it, the round arrow (Game's Climb Speed) puts it back, and the arrow onto the floor (Stabilize Ground Contact) picks the slowest speed that has him fully up when the loop starts (the dip there can't be keyed away, because the loop repeats). The note beside it says when he's fully up against when the loop starts, and where the feet are when the loop takes over. The build writes the speed into the hero's base package (one the borrow ships already), so it applies to every flying power of that hero, in every costume, while the mod is on; it lowers the borrowed start to match, and the 3D view and the Feet line follow it. When the donor has no end animation of its own (Captain America's run has only a start and a loop) the panel has an End choice: Nothing Borrowed plays what the power has (a Sky-Cycle's own end), The Donor's Loop, Landing plays the borrowed loop once more as the end, lowered by the game's landing (down from the flying height at the hero's landing speed, 600 units a second, about 0.23 s), so the feet stay on the floor; it then has its own End part on the strip, and Chain plays it after the loop. The usual order: borrow the power, Stabilize Ground Contact, choose the End, then key the body for the look. On the Powers tab, Climb and Height under the borrowed look opens this panel. Right-click Head, Bust or Full Body under any 3D view to Lock View to the head, torso or body: the camera then follows that part while the animation plays, in every pane of the quad view, so a lowered or moving animation stays on screen (turning and zooming still work). The locked button has a blue border; right-click it again to unlock. Shift+click on the button does the same: it locks the view to that part, and unlocks it on the next Shift+click. The preview shows the ghosts at once (▶ on Dodge Effect plays them), and the Color tab recolors them. Save writes them into the hero's package, so every costume of the hero shows them. Game's Ghosts puts the game's back.

Example: Invisible Woman's hover when she runs a while: Invisible Woman: Character → untick Can Transition to Hover. She keeps running, with no disc, hover effects or hover sound (tested in game). Her travel power (Levitating Disc) is a power of its own: its disc is the Flyingdisc attachment, its glow and sounds are its effects and sounds.

What it changes: Each part is switched off inside the game's own package (an effect's particle system, a sound's events or an attachment set to none, a setting set to false); Save puts that package in the mod as the game's copy with the change, so every costume of the hero is affected, and MHModManager can install the mod too. Tick a part again for the game's own: a package that came in only for its parts leaves the mod.

Borrow Another Hero's Power

  1. Open the hero's mod in the Editor and go to Powers. Pick the power to change.
  2. Click Borrow Power (the lightning bolt with an arrow), pick a Hero and one of their Powers. Keep the suggested mode (Whole Power, or Keep This Power's Timing for powers built differently) and click Borrow. Under Whole Power, untick Animations, Effects and Sounds or Props (Weapons and Vehicles) to keep this power's own of that part (Storm's wind on Cyclops's own Shotgun Beam animation, or Punisher's rocket without his launcher). Tick Its Triggered Powers' Look Too when it shows, so what this power sets off takes the other's look as well. Rename This Power gives it the borrowed power's name (or type your own) and Use Its Icon its icon; they go into the Strings and Icons tabs, and Reset Power takes them off again.

The Mod List

Each mod is a card: its picture (the hero portrait or costume icon it replaces, or the game's own), its name, author, tags, the P T S A badges (Packages, Textures, Strings, Audio) and, on the right, whether it's on and either what it changes or the costume it's for.

  • On / off: the checkbox on the card. Nothing reaches the game until Apply Changes.
  • Priority: the higher mod wins when two change the same file. Drag a card, or use ⤒ ▲ ▼ ⤓ above the list (Ctrl+Up / Ctrl+Down one step, Ctrl+Home / Ctrl+End to the top or bottom).
  • Several at once: Shift+click selects a range, Ctrl+click adds or removes one (Shift+Up / Shift+Down too). Then a checkbox of one of them, or Space, turns them all on or off; dragging one of them, or the priority buttons and keys, moves them together in their order. Esc or a plain click goes back to one. Each of these is one Undo step.
  • Padlocks: a mod at the top or bottom can be locked there (the padlock under its checkbox). Several mods can be locked in a row at each end. A locked mod moves only among the mods locked at the same end (drag, the arrows or Ctrl+arrows reorder them there); other mods can't pass the locks, and new mods land inside them.
  • Conflicts: a stripe on the card's left edge. Red: part of this mod loses to a higher one. Amber: it only wins. The selected mod's partners are outlined, and the Conflicts tab says who wins what.
  • Nexus: an orange N on the picture means the mod is linked to a Nexus page, a green ↑ and an ↑ UPDATE pill mean Nexus has a newer version.
  • ⚠ OVERLAP (a yellow warning pill): the mod changes a model, or a power's effect or texture, that other game files also carry under the same name. Many characters are in several files: Jessica Jones is in her team-up, her summon (Luke Cage's talent) and the Avengers Tower NPC; Angel is in his team-up and in Cyclops' own file. The game uses whichever copy loads first, so near other players, their summons and team-ups, or hub NPCs, the mod can show the game's look instead of its own. Click the pill (or right-click the card → Make Unique) to give the mod's copy names of its own: only the mod's own package files change (saved like an edit), textures the game streams keep their names, and the mod still installs in MHModManager. Then Apply Changes. A mod that ships every file carrying the model doesn't get the pill. Moving a costume to another hero, and saving in the editor, do this by itself. The hero's own copies stay shared: a hero's illusions, afterimages and summons (Jean Grey's and Emma Frost's illusions, Doctor Strange's projections, Nick Fury's agents) carry the costume's model too, and sharing its path is what shows them in the mod's look. So do other heroes' summons of the same character (Cyclops' Call Jean summons Jean Grey in her costume): a Jean Grey mod shows on that summon too, and her own illusions keep the mod's model. A boss or enemy that carries the model is still renamed away, and so is a copy in one of the hero's power packages (Cable's Future Bomb carries every Cable costume's model): a power package can load with the hero's powers, before the costume, and then its game copy shows instead (a Bishop costume on Cable flipped back to Cable this way). That power's copy of the character then shows the game's look. When the mod ships that power package itself (a recolored power), the mod's model is put into it instead, so both show the mod's look; Make Unique and Save do this. Anything another game file imports by its path keeps it: a hero's other costumes take their hammer, physics and attachment classes from the hero's main package (Thor's Earth X takes his hammer from it), so renaming those crashed the game on switching costumes. A mod made unique before version 0.60.272 is put right by opening it in the Editor and saving. Saving also fits those summons to the mod's model: an illusion's see-through material is set on every material slot of the mod's model, and the summon's size changes when the mod changes the character's size (the game's own proportions stay: Jean Grey's illusions are a little bigger than her in the game too); those summons' packages are added to the mod. A mod made unique before these rules (version 0.50.18) is put right by opening it in the Editor and saving: what today's rules keep shared gets its game name back first. Only a model with more bones than the game's is renamed even there, because sharing it with a copy that has fewer bones can crash the game. Before it does anything, the Make Unique window says what it changes: which characters keep the game's look afterwards, and which stay shared. Undo Make Unique (right-click the card) puts the mod's packages back as they were before, as long as nothing changed them since (a Model build, a color, an update), and ticks Keep Shared Paths so saving doesn't rename them again. A mod that shares its paths on purpose shows a blue SHARED pill instead of OVERLAP: hover it for what's shared, click it for what that means, or to make the mod unique after all. Mods made unique before version 0.37.273 have no copy to go back to: restore the old folder from the Recycle Bin, or reinstall the mod's file. The same pill warns about a power package only enemies use (no hero power uses its look: a Taskmaster costume mod that replaced the Taskmaster boss's Shield Toss made the boss throw the costume's shield): click it, or right-click → Remove Enemy-Only Packages, and choose Remove from This Mod or Remove in a Copy (the original stays, so you can switch back).
  • Effect models share on purpose: the Model tab's Effects tab and its summon builds puts the model into every package that holds a copy of it (the ticked ones under Packages), so all the copies the game might load first are the mod's: those don't count as OVERLAP, and Make Unique leaves them. Copies in other characters' packages are the exception: a summon's model can be another hero's costume (Cyclops's Strike Team Beast is Beast's Astonishing costume, and the Beast NPC), andan effect mesh can sit in an enemy's or another hero's package. They're left unticked (tick them under Packages); a summon build asks (Change Them Too or Leave Them, remembered with the mod): changing them changes those characters too; left as the game's, theirs can show near them. The hero's own packages are always included (they load whenever the hero is played). Shared effect libraries (meshes and textures in vfx_shared… and other groups carried by over a thousand packages, such as msh_sphere) are never renamed and never get the OVERLAP pill: a change to one shows on every hero that uses it (Effect Models says "Shared by N heroes" in amber).
  • Keep Shared Paths (Editor → Overview → Details, on the right): sometimes sharing is what you want. A modded S.H.I.E.L.D. agent package also changed Nick Fury's summoned agents, because his summon carries a copy of the same model in his own file; Make Unique took that away. With Keep Shared Paths on, Save leaves the mod's paths as the game's and the mod gets no OVERLAP warning (the choice travels with the mod). The impact: wherever another file carries the same path, the game shows whichever copy loads first, so your look can spread to those characters, or the game's look can show instead of yours near other players and in hubs. Off (the default) is the safer choice: your look stays yours, and characters sharing the path from other files keep the game's look. A CRASH RISK warning still shows either way, and its window still offers Make Unique.
  • ⚠ CRASH RISK (a red warning pill): a model in the mod can crash the game. The game keeps a few lookup tables per model, one entry per bone, and crashes (an Array.h:575 error) when it reads past the end of one. Two things cause it: the mod's model has more bones than another copy of the same model in another game file (added bones for a cape, a dress, wings or a loincloth on a character who is also a summon, an illusion, a team-up or an NPC: the copy loaded first decides the table, and a shorter one crashes the bigger model when both are around), or the model's mirror table doesn't have one entry per bone. Click the pill for every finding: Fix Mirror Tables gives every bone a mirror entry (an added left bone mirrors its right partner, others themselves), and when another copy is the cause, Make Unique fixes it (the mod's model gets a name of its own, so it gets its own tables). Both change only the mod's own package files, saved like an edit. A third cause is a costume moved by an older version: textures whose larger sizes stream from the game's texture cache got a new path the cache doesn't know, and the game hangs, then crashes, when it needs them (Emma Frost's Diamond Form). Move the original mod again to rebuild the copy. Added bones on a model no other file carries are fine. The Model tab's Build into Mod fixes the mirror table of the model it builds by itself and lists the checks in its log, and Save Changes makes the model unique by itself. A summon built into its copies (Squirrelpocalypse's squirrel in two packages, Strike Team's Beast in Beast's costume when you say so) gets the mirror fix in each copy, and the copies are checked together, so the same added bones in all of them aren't a risk; a copy left as the game's (fewer bones) is. Apply Changes

Apply makes the game match your list. It's the only thing that writes into the game folder, and it needs the game closed.

  • For every package a mod names, the highest enabled mod's copy goes in; if none is on, the game's original goes back.
  • Icons, store images and strings are rebuilt from the game's originals with the winning replacements, so turning a mod off really takes its icons out.
  • Sound packs are built into the game's sound files from their originals.
  • Every file is written to a temporary copy, checked, and only then swapped in, with an undo snapshot.

The status line says how many files are waiting ("4 File(s) to Change"). Click it, or press Apply Changes (Ctrl+Enter), to see the plan first; nothing is written until you press Apply in that window. When everything went well the window just closes. If something stops, it stays open with the log: files written before the stop were checked and stay; nothing after it changed.

Checks. The top of the Apply window lists anything unexpected: files that can't be changed because there's no clean original of them, and game files changed by something other than this app (another tool, a mod folder deleted by hand) that Apply leaves as they are. When a file has no clean copy, it suggests Settings → Clean Game Files Folder and explains how to get a clean copy from Steam: verify the game's files in Steam (which takes all mods out of the game folder), copy the CookedPCConsole folder somewhere outside the game folder, choose that copy as the clean folder, then Apply Changes again to put your mods back.

A game file this app wrote earlier that no mod names any more (a mod that dropped a package when it was edited or updated, or a mod folder deleted by hand) goes back to the game's original, the same as when a mod is turned off.

Apply only puts back files that are still what it last wrote or last saw there (it keeps a small record of each game file it manages). If another program (a freecam installer, Package Modifier) or you by hand changed a game file since, even with a mod's own files, Apply leaves it alone, even when a turned-off mod names that file, and lists it under "Left as they are". Turning a mod off still restores the files this app put in for it.

Review Changed Files (in the Apply window when there are any, or Settings → Changed Game Files) lists the game files changed outside this app. Select one or more, then Keep as a Mod (they're copied into one new mod in your list, turned on and at the bottom, so you see them and can turn them off later; the game isn't changed) or Restore to Original (the game's own files go back, from the clean originals, with a .bak made first if there's none; the game must be closed). Files you don't act on stay as they are.

Originals: the app only trusts a copy of a game file as "original" if it matches the stock checksum list (every one of the game's 15,250 packages). Files that were already modded before and have no clean copy are "left as they are" and listed in the plan.

Installing, Updating and Exporting

  • Install Mod (or drag an archive onto the window) takes a .zip, .7z, .rar or a folder. An archive can hold several mods. New mods go to the top of the list, turned off: tick them, then Apply Changes. A mod made for the older MH Texture Manager (a .json and a .tfc instead of a manifest.json) is converted as it's installed: its textures go into the game packages that use them (from the game's stock copies, the new mip levels stored in the package), so it becomes an ordinary mod that turns on and off like any other and leaves the game's texture caches alone. Its name and version come from the Nexus file name when there is one, and its author from that mod's Nexus page (public information; only the page's number is sent; without a connection the author is left as Unknown).
  • Updating: installing a mod whose name you already have asks to replace it. Right-click a card → Update from a File replaces that mod with an archive's mod under any name. Either way the mod keeps its place, on/off, lock, tags and note.
  • Resave: right-click a card → Resave builds the mod again with this version of the Mod Manager and saves it, in a few seconds and without opening the Editor. The result is the same as Edit, then Save (power colors, parts, power sounds, models …): use it after an update of the Mod Manager. If the mod is open in the Editor, the Editor closes first (it asks when there are unsaved changes, which are lost). A mod with dodge ghosts or added props still needs Edit, then Save: only the Editor builds those. If the mod is on, use Apply Changes afterwards.
  • Add Borrowed Power Sockets: some borrowed effects sit on a named point of the other hero's body, such as the glows on Thor's hammer at his palm. A borrow adds that point to every costume of the hero, except costumes that a costume mod in your library replaces, so it never overrides your costume mods. On such a costume those effects don't show. Right-click the costume mod → Add Borrowed Power Sockets adds the points to that mod's own costume models, for the borrow mods in your library for the same hero. It shows what will change and asks first. It changes the costume mod's files, and the costume mod still works on its own. If the mod is on, use Apply Changes afterwards. The item only shows on mods without borrowed powers that replace a hero's packages.
  • Duplicate: right-click a card → Duplicate makes a copy of the mod under a new name (it asks for one: "Name (Copy)" to start): every file comes along, the Model tab's work and the editor's settings too, and your tags, note and picture picks. The copy goes at the top of the list, off, so you can experiment from it while the original stays as it is (turn one on at a time: both change the same game files).
  • Export to ZIP saves the mod as Name - vVersion.zip; a mod with a saved post (Create Post → Save to Mod) also gets its post and images in a folder beside it. If the mod uses features MHModManager doesn't know, you can export a legacy copy without them.

Removing a Mod

Remove Mod (or Del) tells you what will happen and asks once:

  1. the mod is turned off (if it's on);
  2. Apply Changes runs, so the game gets its original files back (other changes waiting in your list are applied too);
  3. its folder goes to the discarded copies (kept 30 days by default; restoring a snapshot from before brings it back: Snapshots).

Several at once: mark them first (Ctrl+click or Shift+click), then Remove Mod or Del. A warning in red lists every mod that will be removed, and Cancel is the default button, so pressing Enter removes nothing. They're turned off together, Apply Changes runs once, and their folders go to the discarded copies. If Apply stops, none of them are removed.

The game must be closed. If Apply stops, the mod isn't removed: it stays in the list, turned off, and the log shows why.

Move to Another Costume

A costume mod made for one costume can be moved onto another costume of the same hero, for example Unworthy Thor (made for Age of Ultron) onto Thor Classic, so you can wear both, or onto a costume of another hero (below).

  1. Select the mod. Its card and header show the costume it's for (only mods for a single costume can move).
  2. Click Costume: … ▾ in the header, or right-click the card → Move to Another Costume, and pick a costume. The list shows each costume's store image and whether other mods already use it; the hero's default costume is marked Default in green.
  3. The Move window shows what moves (the model, materials, animations, weapon or prop, the costume icon, portrait, store image, the costume's name and other text the mod changes, and its sound pack), what's left out, and other mods for that costume.
  4. Press Create Mod. The new mod, "Name (on Costume)", goes to the top of the list; with Turn the new mod on and … off ticked (the default) it's on and the original is off. Then Apply Changes.

The original mod isn't changed. Moving again to a costume you've already moved to selects that mod instead.

The costume icon, portrait and store image must be the game's sizes (40×40, 180×136, 300×420). An image of another size is resized for the move: scaled to fill the frame and centred, so it isn't stretched (what doesn't fit is trimmed), and a message lists what was resized and from which size.

Name in Game, at the bottom of the Move window, is the name the target will show, ready to edit. It starts with the mod's own name for its costume when it has one. On a team-up, that name is made plain: costume names carry color tags and the word "Costume" (ENHANCED Odin Costume), which the team-up unlock window would show as raw text, so it suggests Odin. The line under it says whether anything else in the game shows the same name (most names belong to one costume or team-up; a shared one is named in amber, and renaming changes it there too). Untick it to keep the game's name.

To Another Hero

At the bottom of the costume list, Another Hero opens a picker: the heroes with their portraits (type in Filter to narrow them), then the chosen hero's costumes with their store images (the default in green). The Move window then shows what moves: the model with its materials and textures goes into that costume's package, and the costume icon, portrait, store image and name follow. The voice moves too: the costume's voice set (death, level up, hits, banter, mission lines …) is copied with its sound events, so the target hero's powers play the source's lines: the mod's own voice lines (with its sound pack) if it has them, otherwise the source hero's stock voice. What stays the target hero's: the animations and powers; parts of the model the target's skeleton doesn't move (hair, a cape) stay still. The new mod is "Name (on Storm Modern)": amber for another hero, teal for another costume of the same hero.

The voice moves too. Where the moved voice has no line for a situation the target hero has (a team-up's voice has no "can't do that yet", no death line …), that situation is turned off, so the target hero's own line doesn't play there. The Editor's Audio → Voice tab lists those lines as Not in This Voice; they can't be turned on, since their sounds aren't in the mod.

Team-ups work the same way, in both directions: a team-up mod (Rescue, say) can move onto a hero's costume or another team-up, and a costume mod can move onto a team-up. Team-Up, under Another Hero in the costume list, opens a picker with only the team-ups (in Another Hero's picker they're the first tile, Team-Ups). The team-up's costume icon, portrait and store image take the mod's images. The moved model gets the target's sockets it lacks (where effects attach), and the sockets both have are turned to face the target's way (so a beam fires straight ahead); its animations and powers stay the target's.

To a Pet

Pet, the last item of the costume list, puts the costume on one of the game's vanity pets (a team-up mod too). The picker shows the pets with their store images and names; Full Size keeps the hero's size (unticked: the pet's own, most are shrunk), Name in Game sets the pet's name, and Turn the new mod on turns the copy on without turning the original off. The pet's package gets the model, its physics, its idle, run and fidgets (and the walk and out-of-combat run a hero's animation tree asks for), the costume icon as the pet's item icon and the hero portrait as its store image. Textures the mod stores in its package are kept loaded, as a pet's textures are streamed otherwise. A pet mod's right-click menu has Move to Another Pet: the same picker, with Same Size as … in place of Full Size. Some pets have no picture of their own in the game's data (Mini Kronan names Dragon Man's): the picker shows none, and a move leaves the other pet's picture alone.

Capes and coats simulated with APEX cloth move along with the model, together with the model's own physics setup (the cloth needs it). A few models can't move to another hero yet, for example ones with an animated material. The Move window says so.

Sound packs come along when every sound they play belongs to the costume (as with Miles Morales' voice pack). If the original and its moved copy are both on, the pack is only added once.

How it works: the game finds a costume by its class name and its icons by name, so the moved package is the mod's own package with the costume's class renamed to the target's, the model and materials given their own names (so they can't mix with the original costume's), and the target costume's package ID. Textures the game streams from its texture caches keep their names, as the caches find them by name. A costume that lives in a hero's main package (for example Vision Classic, or a mod that replaces Star-Lord's main package) can't be a target, but it can be moved from: its model is copied into the target costume's own package instead, as for a move to another hero.

Power Colors

The editor's Powers tab recolors the hero's powers. Pick a power in the bar of icons under the 3D preview (hover one for its name; its own effects, parts and added packages follow after a gap). Its animation shows in the preview, paused: press ▶ to play it with its effects, Esc stops it) and turn Hue (around the color wheel), Saturation (0 % is grey) and Brightness; the preview shows the colors at once. Opacity fades the power's effects: 100 % as the game has it, lower makes them see-through, and 0 % switches its emitters off so nothing draws. Use it rather than Brightness to make an effect disappear: smoke, dust and gas are drawn by their transparency, so a darker color only turns them into a dark cloud. Above 100 % (up to 1000 %), Opacity makes the effects more solid: their particles' and effect textures' transparency is multiplied.

Dark powers: the Dark button sets Saturation 0 %, Brightness 0 % and Opacity 500 % (the value that looked right in game on Nova's Magneton Pulsar); the sliders fine-tune it. Translucent effects (energy fields, smoke, dust) simply turn dark. Most glows, sparks and beams are additive: the game adds their light to the scene, so a dark color would add nothing and they would vanish. With a dark color (Brightness 25 % or less), Save therefore draws each additive sprite, beam or trail with a copy of one of the game's translucent effect materials, keeping the effect's own shape, so it darkens too. The impact: mesh effects and distortion (heat haze) keep their own materials, so a few parts of a power can still fade instead of darkening; the 3D preview doesn't show the swapped materials. Check the result in game.

Switching powers keeps the Frame slider's place: the next power opens at the same point of its animation (halfway stays halfway), so you can compare powers at the same moment.

Powers the game keeps under one name in several versions (Iron Man's Unibeam and its talent-upgraded version, Thor's Ragnarok leap and strike) are one entry, and its color goes into every version's packages.

Add Package (beside Apply to All Powers): adds one of the game's effect packages (a UC__Power… file, or a projectile, hotspot or condition effect) to the end of the power bar under its file name, for a power that isn't listed or doesn't change fully. Its color recolors everything in that package, and Save puts the package in the mod. The impact: every hero, team-up or enemy power that uses the package changes too, and the 3D preview doesn't show the color (check it in the game). The Game's Colors and Save take it out again. A character's own package can't be added here: add it on the Packages tab, and its effects show as an Own Effects entry, which keeps its model.

The list has every power the hero's avatar names: those with an animation, the travel power, and also procs, passives and talents that have effects of their own but no animation (Captain Marvel's Radiant Cascade glows during her other attacks). Those play nothing in the preview; their colors show in the game during the powers that set them off.

Change single colors: under the presets, Colors in This Power shows the colors the power really uses (read from its particles, materials and effect textures, the most used first; hover one for its hex code and where it's used). Click one to replace just that color: a row appears with the new color as a hex code (#RRGGBB, for example #20FF40) and a swatch of it. Type a hex, or click the new color's swatch for a color wheel (hue around, strength toward the edge, and a Brightness slider) with an Eyedropper: press it and drag onto any color on the screen (the 3D view, a reference picture in another window), then release to take that color. Under the wheel, Recent keeps your five latest colors (on this PC, for every mod; click one to use it), and Reset takes the color back to the power's own. Each part of the power keeps its own brightness, so a glowing core stays brighter than a faint trail; a darker hex makes that color dimmer too. Range sets how close a color has to be to change with it: small for only that exact color, larger for similar shades (some powers use several close blues). × removes a replacement. You can replace several colors, and use the sliders as well (the replacements come first, then the shift). Game's Colors removes both.

NPCs, enemies and team-ups: when the mod holds an NPC, enemy or team-up package (one the Model tab built onto, for example), or a hero's audio package (Jean Grey's holds her Phoenix form's model, flames and wings), the list ends with <Name>: Own Effects: the effects that package carries itself, such as the Sinister clones' red glow and eye trails. They're recolored the same way (sliders, presets, or one color replaced). The package keeps the model the Model tab built into it, and a copy of it as it was before the recolor stays with the mod, so the color can change or go back to the game's at any time. Picking the entry plays the character's idle in the 3D view with those effects on it, in the colors and opacity you set. A team-up drawn with a hologram material (the Danger Room Wolverine) shows as a cyan glow there; at Opacity 0 % the hologram comes off and the character's own materials show, in the preview and in the saved package. Under each Own Effects entry come that character's own powers, read from the game data (the attacks its AI uses: Black Cat Boss's Punch Flurry and Spinning Roundhouse Kick, the Cyclops clone's eye beam …). They're recolored like a hero's power, play on the character in the 3D view, and the line under the colors names anyone else they'd change (the Wolverine clone's claws use Wolverine's own basic attack). Some characters are built on another one: the Sinister Medal pets (…CloneWolverineMedal_SF) extend the mob clones (…CloneWolverine_SF), so their model and most of their effects, the red glow included, are in the clone's package. Their entry then says where, and Add It to This Mod adds that package (the game's copy) and selects its Own Effects to recolor.

Heroes: a hero's or costume's package gets an Own Effects entry too when it has always-on effects of its own: the particle effects its attachments keep on the character. Ghost Rider's flaming skull is one: two flame effects on his head and neck (no material setting reaches them), and the skull's orange flame light. Only those change: his powers, dodge and death effects, body and bike stay as they are. Recolor them with the sliders or a preset, or set Opacity 0 % to hide the flame. His base package (UC__MarvelPlayer_GhostRider_SF) carries the flame for his costumes that use it (Alejandra Blaze has her own copy in her costume's package): a costume mod such as ModernVU shows Ghost Rider: Own Effects straight away (the costume has no flame of its own), and when you set a color, Save adds the base package to the mod (the game's copy) with it.

Presets: five swatches under the sliders, beside Game's Colors, Dark, Apply to All Powers and Add Package. Right-click one to store the sliders there; click it to use it on the selected power. They're kept on this PC for every mod.

On Save Changes, each colored power's own game files are recolored: its particles, effect textures and material colors, in the power's package and those of what it sets off (missiles, hotspots, conditions, pets and summons; Thor's Rolling Thunder: 6 packages). Effects many heroes share (knockdown, slow, taunt ...) are left as they are. When a few others use the same effects (Beta Ray Bill's team-up copy of Thor's), they change too: the tab names them under the presets. They become ordinary packages of the mod, so Apply Changes puts them in the game like any other, and MHModManager can install the mod too. Nothing on the server changes.

A color changes the power for every costume of that hero, for anyone using the mod: the files are the game's own power packages. Two mods that recolor the same power conflict like any two mods with the same package (the one higher in the list wins). A few effect textures stored uncompressed keep their colors.

Borrow Power

Borrow Power gives one of a hero's powers another hero's power look: Captain America can throw Wolverine with Colossus's Fastball Special instead of his shield, or burst into Human Torch's flames with Shield Bash. The power still does what it always did (the server decides that), so a borrowed power works on any server, for anyone using the mod.

A few powers play no animation of their own: their effects go off while the hero stands in her idle (Invisible Woman's Seeker Orbs, Psylocke's Katana Typhoon). They can borrow a look too, and then play the other power's animation (Seeker Orbs with Jean Grey's Telekinetic Throw). Passive powers and talents can't.

In the Editor's Powers tab, under a power's color sliders, the Borrow Power button (a lightning bolt with an arrow) gives the selected power another hero's power look. Pick the hero and the power; then either:

  • Whole Power: the other power's animation, its effects and sounds, and its projectile's look. For powers built alike (a projectile from a projectile: Human Torch's Burning Volley on Iceman's Icicles). Fit the Animation to This Power's Timing plays the borrowed animation faster or slower so it lasts as long as the power's own (the game repeats the power at its own pace: a longer animation would be cut off).
  • Under Whole Power, Animations, Effects and Sounds and Props (Weapons and Vehicles) choose which parts come over (all ticked at first). Untick one and this power keeps its own of that part: untick Animations to have Cyclops fire Storm's Electrocute from his own eye-beam animation (he keeps his own weapons too), untick Props to borrow Taskmaster's Foeslayer Strike without his shield and sword. At least one stays ticked.
  • Keep This Power's Timing: the power keeps its own animation, timing and sounds; its beams and effects draw the other power's, and the other power's hand effects are added when this one has none. For powers built differently (Human Torch's channeled Incinerating Blast on Iceman's quick Chillblain beam).

The window suggests one from how the two powers are built. Only the look changes: what the power does in the game stays its own (the server decides that), so it works on any server. Only this hero's power packages change (for every costume of the hero, and anyone using the mod); the other hero is untouched. Whole-power borrows also put the borrowed animations into the hero's base package, and into each of the hero's costumes that has an animation list of its own (those don't play the hero's list), so those costume packages become part of the mod too. The preview shows a borrow at once; Save Changes keeps it, and a color set on the same power recolors the borrowed look. The Reset Power button (a circular arrow) takes it off again (the packages it built leave the mod at Save). A borrowed power says whose look it has in the list.

What comes along with a whole power:

  • Weapons and props the other hero holds for it (Punisher's minigun, Deadpool's cannon) come along under names of their own, so the other hero's own copy never stands in for them. Keep This Hero's Weapons keeps the weapons this hero always holds (Captain America's shield) shown while it runs.
  • Thrown characters: Colossus's Fastball Special throws Wolverine, flying and clawing, from the borrowing power's projectile (Captain America's Shield Toss).
  • Models that stretch or change shape: the Thing's Hammer Time, Stretch! brings Mr. Fantastic as the mallet.
  • Charge and release: a power you hold to charge (Human Torch's Extreme Combustion) charges from the start of a single attack and bursts at its hit; on a channeled power (Punisher's Ol' Painless) it charges while you hold and bursts when you let go.
  • Its Summon's Look Too (when both powers summon a model): this power's summon takes the other summon's model and animations (Hawkeye's turret becomes Squirrel Girl's squirrel).
  • Its Area's Look Too (when the other power's look is an area it puts down): that area's effect plays where this power hits (Squirrel Girl's raining squirrels), for about 4 seconds.
  • Its Triggered Powers' Look Too (when both powers set off another power with a look of its own): the powers this one sets off draw the other's instead, their effects and sounds (Venom's Symbiotic Spikes on Magik's Sorcerous Eruption: Venom's spikes from the ground in place of Magik's area). What they do in the game stays this power's.
  • Rename This Power and Use Its Icon give the power the borrowed power's name and icon; they go into the Strings and Icons tabs.

For a travel power borrowed from another hero: a vehicle or mount the other hero rides comes along (Cyclops' bike, Hawkeye's Sky-Cycle, Green Goblin's glider), sized for this hero; this hero's own weapons are hidden while it runs (on a hero whose own ride is kept up by a travel condition, as Hawkeye's Sky-Cycle is, that condition shows the borrowed vehicle and plays the borrowed ride; Kate Bishop keeps her Sky-Cycle); and parts this hero's own run moves but the borrowed animation doesn't (Thor's cape) move as in that run. A borrowed ride doesn't tilt with slopes as it does for its own hero (Cyclops leans with his bike up and down a slope; another hero on it stays level): that tilt comes from the game itself, not from anything a mod can carry.

Prop Fit (under Borrow Power, once the borrowed power brings props: another hero's vehicle, mount or weapons): pick a prop, then Size (a vehicle starts sized for this hero: this hero's height over the other hero's), Move X / Y / Z (game units) and Turn X / Y / Z (degrees), along and about the prop's own axes. The move / turn gizmo works on it too, in the power's own animation: drag a colored arrow to move the prop along X (red), Y (green) or Z (blue), a ring to turn it (5° steps, Shift: 1°); letting go puts the fit in. The buttons under the sliders: Reset Fit (the prop as the borrow brings it) and Gizmo (show or hide it; one setting with the Model tab's). Thor's hammer starts turned to sit right in another hero's hand (Turn Z -170). When the costume holds that prop already (added in the Animations tab, Props: Thor's hammer in Captain America's hand), the power uses the held one: the Prop Fit sliders here are its fit in every animation (the same as the Animations tab's), and In This Animation moves and turns it in the power's animation playing only (along and about the global axes, baked into that animation, with Pivot on the Hand or without). The gizmo works on one or the other: Gizmo: All Animations (beside Reset Fit: the prop's fit) or Gizmo: This Animation Only (in In This Animation: this adjustment); the one lit is the one it changes, and clicking the lit one hides the gizmo. Rider Fit (with a vehicle or mount): Forward / Back, Up / Down and Lean move and tilt this hero on it; the vehicle stays where it is. Double-click a slider to reset it. Each change rebuilds the borrow, then the preview shows it; Save Changes puts it into the mod.

Animations

The Editor's Animations tab lists every animation a costume plays (idle, run, emotes, attacks, power animations …), the power each belongs to, and where it comes from: the hero's own set, the costume's own, or shared ones. A costume's model lists animation sets, and a name in a later set replaces the same name in an earlier one; that's how some stock costumes have their own idle or emotes. A hero with forms (Jean Grey's Phoenix) also has a set per form, which the form switches to: its animations are listed after the others, marked Form in From, with the form's powers in the Power column (they share names with the normal ones). They can be changed like the others: the change goes into the costume's own copy of that form's whole set (the game uses the form's set as a whole, so the copy carries all of its animations, a few MB in the package), with the new animation fitted to that set's bones; the hero and the other costumes keep the game's. Copy From a Character changes normal animations only. Click a row to play it in the 3D view.

Change Animation (or double-click a row) plays another animation in its place. For a costume moved from another character, the window offers the Source (the character the model came from) and the Target (this costume as the game has it) first, each at the animation of the same name; any hero, team-up or other mod follows, with the same name first and every other animation below. Picking one plays it on the costume's model before you use it. Only the costume's own package changes: the hero and the hero's other costumes keep their animations. Changed rows are amber; Back to the Original undoes one. Copy From a Character does many at once: pick a character and every one of its animations with the same name as one of the costume's is listed, ticked (Find narrows them by name or kind, such as Emote or Movement; Tick All / Tick None act on what's shown); Use Ticked puts them all in. Picking the Target there undoes the ticked ones. Changes are saved with the mod.

Height (under the 3D view) raises or lowers a changed animation's body at chosen moments, for example to float a borrowed run or flight higher partway through. Left to right is the animation, up is higher (in game units; the middle line is the animation as it is), with straight lines between the keys. Click to add a key, drag a key to move it (hold Shift for tenths), right-click a key to remove it. Height Gizmo (the gizmo button in the Height bar, lit when on) puts a blue up arrow at the hips in the 3D view, in every pane of the quad view: pause on a frame and drag the arrow up or down (hold Shift for tenths) to raise or lower the body there; the body moves as you drag, and letting go puts a key at that frame (or moves the one already there). Undo, Redo and History in the Height bar (Ctrl+Z, Ctrl+Y on this tab) take back any change to the keys, from the strip, the gizmo, Add Key at Frame or Clear Keys, step by step or by picking a step in History. Add Key at Frame puts a key where the paused animation is; Clear Keys takes them all off. The yellow line follows playback, and Look → Ground in the 3D view shows the floor. The body moves from the hips, spine and leg and arm targets, never the character's root (moving the root sank heroes into the floor in game). Animations changed on this tab take keys, and so do a borrowed power's animations (a travel power's run or flight borrowed on the Powers tab): their keys are kept with the borrow and made again whenever the borrows are rebuilt. A few that store their movement compressed (many of Punisher's) can't, and the strip says so. Keys are saved with the mod and kept when the costume is moved or the model rebuilt.

Props (under the list) are the props added to this costume from other characters (Thor's hammer for Captain America, with his shield staying on his arm). They're added and removed on the Model tab, and fitted there or here (the same fit: Size, Move and Turn, with Gizmo: All Animations and Gizmo: This Animation Only as on the Model and Powers tabs) (Give a Costume Another Character's Prop; Set Up Props on the Model Tab goes there); here is how they move in the animations. Pair one with its character's idles and fidgets (Copy From a Character) so the hand pose fits; Look ▾ → Prop Pivots shows where it's held. Pivot on the Hand holds it in the animations taken from another character the way that character holds it: in the hand where theirs is held, swinging where theirs swings (Thor's fidget02 swings the hammer by its strap). It's worked out from that character's own animation, frame by frame, and baked into the copies; without it, Thor's animations move his hammer bone to where it is on Thor and the hammer floats by Cap's head. In This Animation (for the animation selected in the list) moves and turns the prop further in that animation only, for a pose that wants it elsewhere: Move X / Y / Z along the global axes (the axis gizmo's) and Turn X / Y / Z about them, around the point it hangs on, the same in every frame of that animation; Copy From starts from another animation's adjustment, Reset takes it off. It's baked into that animation (it needs an animation from another character, a Changed row; with Pivot on the Hand or without: without it, the prop's adjustment goes on top of the other character's own motion of the hammer bone).

Model

The Editor's Model tab puts a model of your own on one of the mod's character packages: a Marvel Future Fight character from your own MFF rip, or an FBX file from Blender or anywhere else. The model is fitted to the hero's skeleton, so the hero's own animations, powers and props play on it. The tab has three columns: Source (the model), the Preview, and Target (the package it goes on). Above them, the folders it reads: MFF (your rip), GAME and STOCK (a clean copy of the game's packages); point at one for the full path, click to open it. They're set in Settings → Model.

Source and Target

A small screen? On the Mods tab, drag the dividers beside the mod list and between the preview and the details (double-click the second one for the automatic width). Here, drag the thin dividers between Source, Preview and Target, between Target's list and its Parts / Bone Map / Materials tabs, and above the log, to give a panel more room. Click a heading (SOURCE, TARGET, SIZE IN GAME, LOG) to fold that panel away or back. Sizes and folds are remembered. Settings → UI Scale (80–150 %) makes the whole app's text and controls smaller or larger, from the next start.

Source: MFF Repository (the characters in your MFF repository folder, each with its uniforms; Characters Only leaves out props) or Single Model: one model file (Browse for a Model: FBX, OBJ, DAE, STL, .blend, or XPS / XNALara .xps, .mesh and .mesh.ascii), with the ones you've used listed below; or from the game: Default Game reads each package as the game ships it, Current Modded Game as your mod list has it now (a package an enabled mod replaces is read from the highest of those mods, as Apply puts it in the game, and its row names that mod, with the portrait your mods give it), so a modded costume can be a source too. Both are called From the Game below (Default Game is the default, and From the Game is the Target's own choice; the kind you pick and the Target list you switch to are remembered; in both lists a • in front of a name marks the hero's default costume, as the game data has it: after reworks and visual updates that's often not the package named Base or Classic): a hero costume, team-up, NPC or enemy from the game (the same list as the target's From the Game). Its model is read from the game's stock copy with its color, normal, spec and glow maps (written once as an FBX with the game's bones in data\model\game) and fitted onto the target like an FBX with MHO bones: bones the target doesn't have (a cape's, a coat's) move with their nearest parent. A .blend or XPS file is read through Blender: it makes an FBX of it once (until the file changes), with its armature, weights and textures; an STL has no textures or UVs, so it builds gray. An MFF character's model (its .fbx, .dae or .obj, rigged with MFF's Bip001 bones) is recognized and read as that MFF character, with its folder's textures. Target lists the mod's packages that hold a character (costumes, team-ups, NPCs, pets …). From the Game adds another package to the mod: a hero or costume, a team-up, or one of the game's NPCs and Enemies and Bosses (the 672 with the same humanoid skeleton as the heroes, such as Black Cat Boss, Bullseye Boss or the Civil War bosses), and each hero's summons and power models under that hero (a summon's own package, or the model a power's package plays: Cyclops's Strike Team). Browse for a Package adds any other .upk with a character in it, named like a game package (from the game folder, the game's stock copy is used). When a package holds several characters, ◀ ▶ under the preview picks the one the model is fitted to and replaces. It also lists a costume's props (Captain America's shield, Thor's hammer, guns and blades): pick one, and an MFF character's part takes its place instead of the body. The part most like the prop is ticked under Parts (US Agent's shield for Cap's; tick another to use it), laid over the game's prop, turned onto its axes, scaled to its size and held on the same bone; the Materials tab works on it as on a body. A prop the game skinned into a character's body (Skrull Captain America's shield, on g_shield) comes in as its own row under Source Parts, marked Prop: pick that character as the Source, untick the row and build, and the character is built without it (then add another shield as a prop). The part also stays listed under The Target's Props, marked Built In, so you can add the new shield first and leave the old one out afterwards: unticking it there goes back to the character as the target with that part left out, and Build into Mod does the rest. The game moves the same prop in every animation and power, so the new one is held, carried on the back and thrown where the old one was (see it on the Mods tab's 3D preview with Props on). A costume that shows its hero's model instead of one of its own (Captain America Avengers, Carnage Classic, Venom Classic, Thing Classic, Rogue Modern, Spider-Man Big Time …) works as a target too: the costume gets a copy of its hero's model under its own name, the new model is built onto that, and the hero's other costumes keep the shared one. Body and prop are built one after the other (pick the character, Build into Mod, then the prop, Build into Mod): each build keeps the other's. Each keeps its own Materials tab settings and its own All Materials choice, even when both come from the same source (the prop starts from a copy of the body's), and everything a build adds is named after its target, so the two never share a texture or a material. A round shield can come out turned in its own plane. An FBX or a game model works on a prop too (laid over it the same way), and the prop's own model, edited in Blender, comes back as it is; the Source's panel lists every costume's props, animated ones too (Ghost Rider's bike and chains, marked Animated Prop: models with skeletons of their own) (see Change a Hero's Prop). Right-click a target → Remove (or Delete) takes it off the list: one the tab added leaves the mod with its build, and one of the mod's own packages can get its own copy back or leave the mod (Cancel in the editor brings it back). A model built onto an NPC or enemy shows wherever the game uses that character, with its own animations and powers. Team-ups and some NPCs have animations that set every bone's position (player heroes' only turn the bones), which would pull a new model's arms and shoulders back to the old model's proportions; the build makes them turn the bones like a hero's, so the new model keeps its own shape (the build log's anim: line says so). A single model's textures are looked for in its own folder and two levels of subfolders, then in the folders beside it (such as a Textures folder next to the model's folder), by the material's name or the file names the FBX stores; then where the FBX says the file is (any folder on disk). Textures embedded in the FBX (Blender's Embed Textures) are read too (PNG, JPG and BMP; TGA and DDS aren't read). With no source picked, the preview shows the target's own model. Build From chooses what a build starts from: Before the Model (the default: the mod's package as it was before the tab built onto it, so the mod's other changes in it stay, and building again replaces the earlier build) or The Game's Stock.

An FBX can be:

  • Rigged with MHO bones (g_ names, as Full Export writes them): used as it is.
  • Rigged with other bone names (Mixamo, or other skeletons): the bones are matched to the hero's by name, or guessed from the skeleton's shape. The Bone Map shows the FBX's own names, guessed pairs in amber.
  • Rigged with a skeleton the tool doesn't know (not MHO names, and nothing it can match or guess: a few bones, a prop rig): its bones are left out and it's treated as not rigged (below); the log says so.
  • Not rigged (a mesh only): it's stood up and turned to face front, scaled to the hero's height, and rigged in Blender with automatic weights (Blender is needed; it runs in the background on your own startup scene). Face, hair and palm bones are left out of the weighting, and everything above the neck goes to the head. Full Export ▾ → Open the Rig in Blender opens the rig to fix weights by hand: each Ctrl+S there reloads the preview. Rig Again starts over.

Parts and Bone Map

Parts: tick the parts of the model to use (Default Parts goes back to the importer's choice). Weapons, effects and other props are listed unticked (kind Prop), also pieces cut out of a body part because they hang on an MFF weapon bone (Blade's swords, Red She-Hulk's weapon: "· BoneW"); tick one to build it into the body. Smooth (Subdivide) rounds off older low-poly models. Add Rigs ▾ gives a hero moving parts it has no bones for: a Cape, long Hair (1–3, or Mega Hair stretched to the model's own hair length), a Coat, a Dress, a Loincloth, a Tail, Chains or Wings. Each kind has its own list (None, then numbered donors); several kinds can be on at once, and the button shows what's added. Bones are added so the model's own strips, strands or tail ride them, and every animation gets motion matched from a hero whose part of that kind is hand-animated (Coat 1 and 2: Blade's and Nick Fury's; Dress 1–3: Angela's, Emma Frost's, Black Cat's; Loincloth 1–3: Iron Fist's, Scarlet Witch's, Doctor Strange's; Tail 1 and 2: Nightcrawler's, Squirrel Girl's; Chains: Luke Cage's; Wings 1–4: the Angel, Archangel and Wasp team-ups' wings, and Black Bolt's cape webbing with small beats). A hero with its own bones of a kind always keeps them; that kind shows as the hero's own and adds nothing. A coat and a dress (or a cape and wings) hang in the same place: the model's strips pair with whichever is nearer. Remove All takes every added rig off.

Bone Map: which hero bone each of the model's bones drives, and which chain its hair, cape and strap chains ride. Click a hero bone to change it. Smooth Weights softens the selected bone's weights (each click another pass; Undo takes it back); Weights paints the model by how much the selected bones move it (blue none, red all); key W steps through off, the weight colours over the textured model at 50 %, and the weight colours alone; Bones shows the skeleton (key B; Ctrl+click a bone in the preview to pick it here). Reset to Automatic forgets your changes.

Paint (under the filter; key Shift+P) paints the selected bone's weights on the model, as Blender's weight painting: Weights turns on with it (over the model at 50 %; W for the weights alone) and shows the bone, the left mouse button paints, the middle button turns the view (Shift + middle moves it). Brushes: Draw pulls the weight toward Weight, Add and Subtract change it by Weight, Blur evens it out with the vertices around. Hold Shift to blur with any brush and Ctrl to paint the other way (Draw toward 1 − Weight, Add and Subtract swapped). While painting, Ctrl+Shift+click picks the bone under the mouse (Ctrl+click alone paints), and Weights shows only the bone being painted; a chain's row (hair, a cape) has several bones: pick the one to paint in the bone list beside the brushes. [ and ] step to the bone above (the parent) and below (a child) in the skeleton. Strength is how much one dab changes, Radius the circle's size; in the view, F changes the radius and Shift+F the strength as you move the mouse (click to keep, Esc to put it back). The brush reaches every part of the model it touches (a jacket over a shirt), and seams paint as one. Each vertex's weights stay summed to 1: what the bone gains is taken from the vertex's other bones. Mirror paints the other side too (left and right bones swap). Invert Bone turns each weight of the bone into 1 minus it, Smooth Bone smooths it over the whole model, Clear Paint takes all the painting off. Every stroke is one Undo step (Ctrl+Z, Ctrl+Y). A source picked by a click on the left is an Undo step too: Ctrl+Z puts the source before it back (a model put on the character, or on an added prop, by mistake). History (beside Undo and Redo at the top right of the Model tab) lists every step by name (each paint stroke, Invert Bone, a bone map change, parts, materials …) with the one now marked; click a step to go back or forward to it. The painting is saved with the mod for this model on this target, applied after the fit, so Build, the preview and Open in Blender all use it; if the model's parts or vertices change (Smooth (Subdivide), a mesh edited in Blender), the paint on the parts that changed is dropped and the log says how many vertices.

Materials

Each material's maps and where they come from: Color, Normal, Spec, MHO Spec, Spec Color, Glow and Alpha. A map is the model's own (found beside it, by name: <material>_n, _sp, _mhospec, _speccolor, _glow, _alpha, or named in the FBX), your file, made by the importer (a normal map and a spec map from the color map), or none. Double-click a row to see its map large, made ones too. Preview Shows switches the preview to one map or spec channel at a time. The buttons (point at one for its name):

  • Replace File puts your own image in for the selected map (copied into the mod); Back to Automatic takes it out again.
  • Generate Normal Map (right-click a Color or Normal row) makes the material's normal map from its color map, bright parts raised, and uses it in place of the one it has: Soft, Medium (what the importer makes on its own), Strong, or Medium, Dark Is Raised. With no source picked, it replaces the normal-map texture in the mod's copy of the package. Undo takes it back. Every normal map the tab writes is set up the way the game reads its own (sRGB off, normal-map compression); one read as a color image lights wrong and shows seams across faces.
  • Generate Spec Map (right-click a Color, Spec or MHO Spec row) makes the material's shine from its color map in the way you pick: Soft, Strong, Dark Is Shiny, Detail or Flat (the recipes Next Recipe steps through). With no source picked, it replaces the shine channel of the package's packed spec texture and keeps its other channels (power, skin mask, reflectivity, glow). The same menu has Tag Colors and From Channels when the row allows them. Tag Colors works with no source picked too: tag the groups of the package's color texture and its packed spec texture is made from your tags in its own layout (shine, power, skin mask and reflectivity from the tags; a glow channel lit where a group is tagged Glow); untagged parts, and channels the tags don't set (rim mask, ambient, height), keep what they have. The tags are kept with the mod, so the window opens with them next time. Double-clicking a spec map (MHO Spec, Spec (Packed)) shows its colors without its alpha, since the alpha is a channel (reflectivity), not transparency; the buttons above it show RGBA, or one channel by name as gray (B: Skin Mask shows where skin shading applies). Edit in Image Editor works on a map the app made too (from your tags, a generated normal or spec map, a glow map): your first save there becomes the material's own file, and Back to Automatic goes back to the made one. Generate Spec Color Map (right-click a Color or Spec Color row) makes the map that tints the highlights: From the Color Map, Color Map, Half Tint, White (No Tint) or One Color (the color picker). A source model's spec color map is used when the material is built with the Metal game material; with no source picked, it replaces the package's own spec color texture. Undo takes either back.
  • Adjust Colors (on a Color row; also in its right-click menu) changes a material's color map without editing the file: Hue, Saturation and Brightness as on the Powers tab, and Levels (Input Black and White, Gamma, Output Black and White), with the map before and after side by side. The preview, Build and Export FBX use the adjusted map; the values are kept with the material (the button is lit while a map is adjusted), Undo takes a change back, and Back to Automatic on the Color row clears it. Color tags are still matched on the map as it was. Export Maps saves every material's maps, made ones too, under the names the import reads, so they can be edited and used again.
  • This Material ▾ (it shows the selected material's choice, and the table's Slot column shows each material's): which of the game's materials the selected material is built from. Same as All Materials takes the choice All Materials (above, beside Preview Shows) sets for every material. Cloth and Skin (Punisher's material), Metal (Angela's armor: its own reflection image and spec color), Glow (Angela's weapon: a glow slot) and The Costume's Own (the target's own material) set it by hand. Each material can have its own, so a model with a body and armor can build the body in cloth and the armor in metal. The game can't make new shaders, so these are copies of materials it already has. The Slot column shows the choice; the preview follows it.
  • Slot (a column; Slot Up / Slot Down): the game material slot each material is built into, 0 first (by default the model's own order). Some costumes' effects name slots by number: Hulk's revive visual paints the skin on every slot but the pants slot, Doctor Doom's force field tells body from cape, Rogue's healing shields and Vision's stealth do the same. For such a costume a line under the buttons says which slots its effects keep; move your materials so the body, pants or cape sit in those slots, and the effect lands right. The build log's slots: lines say the same.
  • OpenGL Normals: for a normal map made the OpenGL way (Blender, Unity, Maya, Substance's OpenGL preset), whose bumps look dented. A normal map the importer makes is already right.
  • Next Recipe steps a made spec map through its recipes: Soft, Strong, Dark Is Shiny, Detail and Flat.
  • MHO Spec is a spec map in the game's own packed form: R shine, G power, B skin mask, A reflectivity (what makes metal look like metal). Layout ▾ says which of the game's six packings a map is in (read from its name when it carries one); others are converted, and a glow channel becomes the material's glow map. From Channels builds one from four gray images: image editors such as Photoshop show a PNG's alpha as transparency and can change the colors under it when saving, so the export writes each MHO spec map as gray _R, _G, _B, _A images too, and newer channel files are read back. A map whose alpha is white everywhere, or that has no alpha, reflects at full strength over the whole material (a white glare, worst with Metal + Glow): the row then says ⚠ Reflectivity (A) full everywhere, and the build log warns too. Put a gray mask in the alpha (black = no reflection).
  • Tag Colors makes the spec map from what each color group is made of: Metal, Skin, Leather, Cloth or Glow (values measured on the game's own maps). Point at a group to see where it is; click the picture to find a color's group. The Eyedropper (or a double-click on the picture) makes a color a group of its own, for small details such as eye whites; Reach sets how far a group takes in neighboring shades. The mouse wheel zooms the picture, right-drag moves it.
  • No Glow (on a Glow row) turns a material's glow off.

Size in Game makes the character larger or smaller in game (5–400 % of the game's own size; double-click for 100 %). It's written as the costume's mesh scale, the way the game sizes its own costumes (Spider-Man Homecoming, Wolverine, Carnage …), so the whole posed character is scaled: the animations keep their shape and the feet stay on the ground. The preview shows it; Compare shows the hero at the game's size. It works without a model too: with no source picked, pick the costume package under Target, set the size and click Build into Mod to write only the size (a model built in earlier stays). Sizing again replaces the size; 100 % puts the game's back. Feet moves the whole model up or down in game (units): the game's animations hold the hips at the stock hero's height and the legs hang from there, so a model with shorter legs would hover and one with longer legs would sink into the floor. The slider starts at the automatic amount for the model and target (marked Auto: the model's lowest point in the hero's idle, moved to the floor); move it if the feet still float or sink in an animation (a very different body: Hulk on Black Widow), double-click to go back to automatic. The preview shows it; Build writes it (the log says how far). Lean (under Feet) tips the model (an MFF model, an FBX or one from the game) forward (+) or back (−), in degrees: half at the ankles (the legs stay straight) and half at the hips, so a large lean doesn't crease the ankles; the soles stay flat. It starts at an automatic amount (marked Auto): the head over the feet as the hero's own model stands in its idle. Move it if the model still tips; double-click goes back to automatic. (Mods made before this keep the Lean they had.) An MFF model is fitted to the target's height by default (Hulk on Black Widow comes out her height); Keep the Source's Size keeps its own size against the other MFF characters instead (Hulk stays Hulk-sized on any hero), and Size in Game and Feet start from there. Match Steps to Size (on by default) keeps the feet from sliding: the game moves a character at the same speed whatever its size, so the costume's run, walk and other movement animations play slower for a bigger character and faster for a smaller one (at 1 / size; landings and jumps keep their timing). Only this costume's animations change: they're copied into its own package, as the Animations tab does. Game Joint Blend (a test feature, off by default) shares the skin around the hips, knees, shoulders and elbows between the limb and the body the way the target's own game model does, over a wide band, instead of the MFF model's narrow handover: the seat stops creasing and the shoulders and thighs bulge less when the hero moves, and the pelvis turns where the game's does. Compare it in the preview (Look ▾ → Weights shows the result), then in game.

All Materials (on the Materials tab, beside Preview Shows) picks the game material the whole model is built with (a material's own choice under This Material ▾ overrides it): Automatic (from the maps: Angela's armor material for metal and MHO spec maps, her weapon material when something glows, else Punisher's cloth), or one of them by hand.

Preview, Build and Blender

The preview works like the others (P plays, Esc pauses, Look, framing, full screen). Compare shows the hero's own model in the same pose. Single Animation ▾ exports just the picked animation, or brings back edits made to it in Blender.

Build into Mod puts the model into the picked package (and onto any other model the character swaps to: Ant-Man's shrunk model, fitted to its own size); Save Changes keeps it and Apply Changes puts it in the game like any other package of the mod. A change the build hasn't put in yet (a new source, parts, materials, the bone map, the size, a Blender edit) is not lost silently: leaving the Model tab asks Build Now, Stay on Model or Leave It Unbuilt, and Save Changes asks Build and Save, Save Without Building or Cancel. Full Export ▾ writes the model and all the hero's animations as FBX files (Export FBX), or opens them in a new Blender scene (Open in Blender). In that scene, every Ctrl+S sends what you changed (the mesh, its weights, bones moved in Edit Mode, the animations whose keys changed) back to the tab, from a Single Animation scene too; a moved bone keeps its orientation and only its joint moves; the status line turns green, and the next build uses it. On the Materials tab, double-click a row to see its map large (zoom, Export as PNG, and Edit in your image editor, or E), or right-click it for View Large, Edit in Image Editor, Replace File, Generate Normal Map, Generate Spec Map, Generate Spec Color Map and Back to Automatic. Ctrl+click the model in the preview to select the material under the mouse (a model with several materials). With no source picked, the tab lists the shown package's own textures (a model built into the mod earlier, or the game's): Edit in Image Editor, Replace File and Adjust Colors (Color rows) change them right in the mod's copy of the package, encoded like the original (DXT1 or DXT5, its size, with mipmaps); an adjusted texture is the texture itself from then on, so adjusting again starts from it. Edit in Image Editor (Materials tab, the pencil) opens the selected map in your image editor: GIMP, Photoshop, Corel PHOTO-PAINT, Affinity Photo, Krita or Paint.NET are found when installed, or pick any program in Settings → Model → Choose Image Editor. It's a PNG copy in the mod's Model folder; every save there comes back into the tab as that map, like Replace File (keep its name and PNG format: in GIMP, export with Ctrl+E; Ctrl+S only saves GIMP's own .xcf, which the app doesn't see). Texture Paint in Blender works the same way: Ctrl+S also saves the painted images (in a scene opened before 0.37.178, save the image itself with Image → Save), and each painted texture comes into the Materials tab as that material's map (color, normal, spec, glow …, by its file name), the same as Replace File; the 3D view shows it, the next build uses it, and Back to Automatic undoes it. Settings → Model sets the MFF folder (Change MFF Folder: your rip's top folder; its models can be in Models\Models, Models or right in it, its textures in Texture2D, Texture2D\Texture2D or Textures, all found), sets the folder Browse for a Model opens in (Change Models Folder; not set, it opens where you last picked a model), chooses the Blender and the image editor, installs the optional MHO Actions add-on, opens the exports folder, and Clean Up Exports and Rigs lists old exports and rigs to delete. Undo and Redo (Ctrl+Z / Ctrl+Y) cover the parts, the bone map, the material and the Materials tab. The ⛶ in the log's top right corner shows the log full screen (it keeps filling during a build); Esc or ⛶ come back.

The tab's work (your choices, bone map changes, material files, the rig and FBX edits, and the package as it was before the model) is kept in the mod's Model folder, so editing the mod later continues where you left off. A full export carries it along; a legacy export leaves it out. Only the game's existing packages change, and only through Apply Changes; nothing on the server changes.

Voice Lines

The Editor's Audio → Voice tab lists the voice set of the mod's costume packages: the Situation (Death, Level Up, Crit Hit Landed, Banter …), extra Detail (the enemy type or mission) and the Sound Event it plays. Only costumes with their own voice set have lines here: a voice mod, or a costume moved to another hero (which brings its voice along). For any other costume, Use Another Voice (or the hero's-voice button the tab offers) puts a voice in first.

To shift a voice (for example a female voice to male):

  1. Open the mod in the Editor and go to Audio → Voice. If no lines show, use the button above the list (or Use Another Voice) to put the hero's voice in.
  2. Click Female → Male or Male → Female as a start, then adjust Pitch, Formant and Warmth. Press ▶ on a few lines to hear the result; nothing changes in the mod yet.
  3. Click Apply to This Voice (about 30 seconds), then Save Changes.
  4. Turn the mod on and Apply Changes; the costume speaks with the shifted voice in game.
  • ▶ plays a line: from the mod's own sound pack if it has that line, otherwise from the game's sound files. Stop stops it. If a line has no sound anywhere, it says so; it's silent in the game too.
  • Untick a line to turn it off, for example when a voice borrowed from another hero names its own team. Save Changes writes it into the mod's package; the mod remembers what was turned off, so it can be ticked again later (or Turn All On).
  • What's Said shows the words of each line (15,200 of the game's 15,400 voice lines). They were written down by speech recognition, so a word can be off. A line of your own shows (Your Own Line). Find searches them too: type hammer to find every line about a hammer.
  • Find narrows the list by words in the situation, detail, what's said or event.
  • Undo, Redo (Ctrl+Z, Ctrl+Y) and History take back replaced lines you don't like, a Voice Shift, another voice, ticked lines and sound packs, step by step or by picking a step in History. They last until the editor closes; after that, right-click a line → Back to the Original Line takes your file out. If another tab rebuilt the package after a step (a Model build), that step can't be taken back, so it isn't lost.
  • Export Lines saves every line as a .WAV named after its sound event, with lines.csv saying when each plays and what's said (select several rows to save only those). Edit them in any audio or voice tool, or record your own.
  • Replace Lines takes a folder of .WAV, .MP3, .OGG, .FLAC, .M4A or .WMA files with those names: the lines that match are replaced and the rest stay as they are, so you only need the ones you changed. Any sample rate, mono or stereo. Right-click a row for Replace This Line, Export This Line or Back to the Original Line. Replaced lines keep your audio through a later Voice Shift: the whole voice's volume and effects reach them, its pitch, formant and warmth don't. They go into the mod's sound pack, so the old MHModManager installs them too.
  • Use Another Voice gives the costume a whole voice from the game. Its hero's own voice comes first: a stock costume has no voice set of its own (it uses its hero's), so this is how you get its lines to play and turn off. Below it are the other voices the game has, such as Lady Deadpool, Spider-Gwen or Jane Foster, and the costumes with a voice of their own (Captain America's American Dream, Captain Marvel's Binary, Iron Man's Extremis …), and under Other Heroes every hero's voice. A mod that ships only the hero's own package (Sentry on Vision Classic, which has no costume package) can change that package's voice: the menu marks it (the Hero's Own Voice), as every costume of that hero without a voice of its own uses it. The costume's powers then play that voice's lines. Back to This Mod's Voice undoes it before you save.
  • Some entries aren't sounds: a Banter Target names a character other heroes' banter is about, and some emotes name an animation. They have no ▶ and aren't shifted.
  • If the mod's packages have no voice lines, a line above the list says where the hero's voice is in the game. Some heroes keep it outside their main package: Carnage's comes from his Classic costume, which plays the Carnage voice package. Add Classic and Use Its Voice adds that costume's package to the mod (the game's copy) with the voice put in, so it can be played, turned off and shifted. When the mod is for one of the hero's other costumes (White Tiger on Iron Fist Classic), the button is Use plus the voice's name instead: the voice goes into that costume's own package, so the shift reaches the costume the mod changes.
  • Voice Shift makes the voice higher or lower, for example to turn a female voice male or the other way round. Pitch moves the voice in semitones, Formant moves the size of the throat you hear (lower sounds bigger), and Warmth adds body (a raised voice can sound thin). Female → Male and Male → Female are starting points; Original sets everything back to 0. While you move the sliders, ▶ plays the original line at those settings. Apply to This Voice shifts every line that is on (about 30 seconds) and Save Changes puts it into the mod; the line next to the buttons shows the saved settings, and ▶ then plays the lines as the mod has them. Remove Shift brings the original lines back.
  • Volume (5 to 300 %) sets how loud the voice plays. A line can't go past full level: above that, its peaks are rounded off.
  • Effects (the rows under Voice Shift) filter the voice, each from Off to 100 %: Reverb (a room, up to a hall), Echo (repeats every quarter second), Distortion (gritty to heavily clipped), Lo-Fi (radio or old speaker: a narrow band, fewer bits), Chorus (doubled, wavering) and Robot (metallic ring modulation). They combine with each other and with the shift; ▶ previews them, and Apply to This Voice puts them in with the shift. Reverb and echo let a line ring out up to about a second longer. No Effects turns them all off. Like the shift, the result is a sound pack MHModManager can install too.
  • Only the costume's voice lines are shifted. Sound effects in its voice set (such as a dodge), the hero's other costumes and every other character keep their sounds. The shift goes into the mod as a sound pack, so the old MHModManager installs it too. Use Another Voice drops a shift: shift the new voice again if you want it.

Whole Set or Selected Rows

The sliders on the Voice and Power Sounds tabs work two ways. Settings For chooses which.

  • Whole Voice or All Sounds: the sliders are every row's settings. Nothing changes until you press Apply to This Voice or Apply to All Sounds. While you move them, ▶ previews them.
  • Selected Lines or Selected Sounds: select rows (Ctrl or Shift for several) and the sliders show the first one. Each slider you move is set on all of them at once, and only that slider. Save Changes builds them.
  • The Settings column shows what each row follows. Green Whole Voice or Whole Set means it follows the set. Amber This Line or This Sound means it has its own settings, listed beside it. Empty means it plays as it is. Type This in Find to list the rows you changed by hand.
  • A row's own settings take the place of the whole set's. Its first change starts from what it plays with now, so turning one line down in a shifted voice keeps the shift. After that, changing the set leaves it alone.
  • If rows have their own settings when you apply to everything, the app asks: Keep Their Settings or Override Them.
  • Back to the Whole Voice or Back to the Set (a button, and on a row's right-click menu) drops a row's own settings. On Power Sounds, setting a row back to 100 % with no effects leaves it out of the set: it says This Sound: As It Is.
  • Your own audio: it stays in the mod as you imported it, so you can change these as often as you like without losing quality. The whole voice reaches a replaced line with its volume and effects only, not its pitch, formant or warmth. A line's own settings can use them all.
  • A sound that picks at random: many power sounds, such as gunshots, choose among several variations. A changed sound can keep only the first, so firing sounds the same each time. Note says so on those rows (Only 1 of Its 4 Variations Plays). To keep the variety, leave that row out of the set.
  • Sounds that loop (a flight hum, a held beam) change like any other and end when the power ends. Your audio repeats from start to end, so a file that fades in or out will be heard fading on each repeat. A few Loop rows are music or filter switches, not sounds: Note says so, and they can only be turned off.
  • Rows sharing a sound share its settings, like Off: the game has one copy of it.

Power Sounds

Audio → Power Sounds lists the sound effects of a hero's powers, and of what those powers set off: projectiles, hits and conditions. It opens on the mod's hero; Hero picks another.

  • ▶ plays a sound, Stop stops it. Find narrows the list by power, part or event. When says when in the power it plays, as far as the game says.
  • Untick a sound to turn it off; Turn All On brings them all back. Many sounds play from more than one place: Taskmaster's .45 Caliber and Dual Wield fire the same gunshot. Note says so (Also in Dual Wield), and unticking one asks whether to turn them all off. Replacing a sound always changes every place of this hero that plays it.
  • Export Sounds saves them as .WAV files named after their sound events, with lines.csv saying which power each belongs to (select rows to save only those). Replace Sounds takes a folder of .WAV, .MP3, .OGG, .FLAC, .M4A or .WMA files with those names; right-click a row for Replace This Sound or Back to the Original Sound. A sound used by two parts of a power changes in both.
  • Volume and the effects (Reverb, Echo, Distortion, Lo-Fi, Chorus, Robot) work on the game's sounds and on your own. See Whole Set or Selected Rows.
  • Sounds marked Loops repeat while a power runs. They can be replaced too, and they stop when the power ends.
  • Undo, Redo and History are the same as on the Voice tab, and share its steps.
  • Save Changes builds them: the power's package joins the mod and the audio goes into its sound pack, so the old MHModManager installs it too. A power's package is shared, so the change applies to every costume of that hero. Sounds that many heroes share (knockdowns, slows) aren't listed. Sounds played by animations, such as footsteps, aren't in this list.

Icons and Create from 3D

In the icon, store and portrait tabs, Create from 3D makes the image from the character itself: frame it (drag, pan, zoom), pick a pose and frame from the animations, a lens and the light, Spec / Reflect / Glow / Effects (shared with the main preview; the snapshot is taken as shown; Effects adds the character's own glows and flames, such as Ghost Rider's burning head, run for a few seconds on the pose so they're fully grown; on a transparent background their light keeps its color with see-through edges), show the weapon or prop, and lay the game's original over it to line things up (O). Thirds, Center and Safe Area draw framing guides over the view (rule-of-thirds lines, a center cross, a dashed frame 8 % inside each edge); they're never in the snapshot. Characters start facing the camera; the Turn slider turns them (0° = straight on), the Zoom slider under it brings the camera closer or farther for exact framing (100 % = the whole model framed; click its number to type a value, or use the arrow keys), and Reset View goes back to the usual framing, facing front, with the standard lens and light. The snapshot is made at the original's exact size (the game only takes that size). For a post or promo shot, Save Large PNG ▾ saves the framed view at 1024 or 2048 pixels, square (more room at the sides) or in the icon's shape, on the same background; it stays out of the mod. Each icon remembers its setup; Use Previous Setup copies the last one.

Click the Original, Replacement or Snapshot picture to look closer: fit, 1:1, zoom, full screen (F11) and save as PNG (Ctrl+S).

Extract

Extract (the picture icon beside Install Mod in the top bar) saves the game's own images (as .dds or .png) and strings (as a language .json in the mod format), always from the clean originals, never from files mods have changed.

FreeCam Options

FreeCam Options (the tab next to Editor) adds options to Marvel Heroes FreeCam (M.H.F.C.) by Michael (MichaelMerc on Nexus). The orbit camera, RB height, the mouse camera and the visible walls are his work; FreeCam Options needs his mod installed with its Full option (it changes the game's MarvelGame.upk and adds the loader that lets the game start with it). The tab shows whether Freecam is installed; if it isn't, Freecam on Nexus opens his page.

  • Cycle Camera Mode (F8 by default): cycles Free Orbit (Freecam's camera) → Locked Behind (the camera follows the way your hero faces) → Default MHO (the game's own camera direction).
  • Snap Behind / Free Orbit (F4 by default): swings the camera behind your hero once and switches to Free Orbit, free to turn again, from any mode.
  • Locked Behind and Default MHO: a key or button for each, to switch straight to that mode (none set at first). Snap Behind / Free Orbit is the way straight to Free Orbit.
  • Gamepad buttons: each action can have a button (with or without holding RT) and picks how it is pressed: a short press, a long press (held for the Long Press Time, 1,000 ms at first; it acts while you hold), a double press, or Short Then Long (a tap, then press again and hold for the Long Press Time). None: the gamepad doesn't do that action. On a button that uses Short Then Long, a double press acts when you let go of the second press. Actions can share a button with different presses; up to three different buttons can be used. A short press waits a moment for a second one only when an action on that button uses the double press.
  • Selfie (F3 by default): like Snap Behind, from the front, facing your hero (it switches to Free Orbit too).
  • Snap Behind and Selfie panels: the tilt and camera height each one sets, and Keep Current In-Game Zoom (or a set zoom: the game's closest view times the factor shown).
  • Invert Y: a setting, remembered between sessions (no key).
  • Remember Camera on Launch (on at first): the game starts, and changes zones, with the camera mode, zoom and angle you last had. The game's own script saves them in its settings file whenever they change and the camera is at rest (FreeCam Options keeps them in two of the game's HUD settings, the console font size and offset). MEMM puts them back to the game's own values whenever FreeCam Options isn't in the game: on Remove, when the Mods tab's Apply replaces MarvelGame.upk, and when MEMM starts (after Freecam was reinstalled, for example).
  • A key or button you pick overrides what it did; Remove gives it back. Under each choice: what it does now.
  • Each card has an ⓘ beside its title: point at it for what the card's settings do. Options holds Invert Y, Remember Camera on Launch, the Long Press Time and the Overhead Labels.
  • Zoom: the mouse wheel carries on past the game's closest and farthest steps, by the number of extra steps you allow; scrolling back takes the extra steps off first.
  • Default MHO Mode: the game's own camera direction. Game's Tilt, a Height of Normal and Keep Current In-Game Zoom (the defaults) make it the base game's camera; untick Game's Tilt to set how far it looks down, set a height, or untick Keep Current In-Game Zoom to start at the Zoom shown (as on Snap Behind: 1 × is the game's closest view, 0.5 × twice as far). The game's own zoom step nearest that distance is used, so its angle and height apply and the wheel carries on through the game's steps; only past the game's farthest step does the extra zoom make up the rest.
  • Camera: how far the camera may tilt down and up, and how fast it orbits. Locked Behind Mode: the shoulder offset, how fast the camera swings behind your hero, its tilt when you switch to it, Lock Tilt (it stays at that tilt: the stick and mouse camera don't tilt it), and Keep Current In-Game Zoom (or the zoom it starts at, as on Snap Behind).
  • Overhead Labels: Hide Names, Hide Titles and Hide Guild Names take that text off the labels over characters (players too, yours included); Hide Level Numbers takes off the level number and its badge. Health bars and markers stay. This changes the game's MarvelHUD_SF.upk.
  • View Distance: buildings, enemies and props farther away pop in because the server only sends the part of the zone around you (3200 by default). Typing !aoi volume 5000 in the game's chat has it send more (5000 is the most it takes, about 2.4× the area), and the server keeps it for your account. Type it: the chat box doesn't take pasted text. !aoi volume shows yours, !aoi volume reset puts it back. It's the server's own command, so a server that turned it off won't take it.

Apply to Game (game closed) builds MarvelGame.upk from your Freecam with these settings, checks it, writes it (with undo history) and sets the keys in the game's input settings; with a label hidden it also writes MarvelHUD_SF.upk (built from the copy it found there, which it keeps). Remove puts Freecam's own MarvelGame.upk back exactly as its installer left it (so Freecam's installer can still update or uninstall it), puts MarvelHUD_SF.upk back as it was and takes the keys out. Nothing else in the game changes, and nothing on the server. Apply Changes on the Mods tab leaves both files alone. See Set Up the Camera with FreeCam Options.

The Data Folder

Everything the app keeps is in data next to the program. Each normal start clears what nothing needs any more, so you don't have to:

  • converted: images converted for the editor (PNG to DDS, Create from 3D snapshots). Save copies them into the mod, so the copies here aren't needed after the app closes.
  • downloads: mods downloaded from Nexus for a one-click update, once installed. update: an app update that stopped part way.
  • model\converted: the FBX copies Blender made of .blend and XPS models, once their file is gone or they haven't been used for 30 days and aren't in the model list (made again when picked).
  • model\inherit: the Model tab's copies of costumes with their hero's model in them (made again when needed).
  • model\thumbs: thumbnails of model files that no longer exist, and any not shown for 30 days (made again when needed).
  • The editor's work folders in library (model-work-…, power-colors-…, voice-…, anim-work-…, costume-move-…) that a closed or crashed run left.

library\discarded holds mods' replaced and removed folders, for snapshot restores: Settings → Snapshots shows their size, how long they're kept and Clean Up Discarded.

Keep the rest: library (your mods, the game's clean originals the app restores from, its list), settings.json, and history (a small record of each game file the app wrote, so Apply can tell its own changes from other programs'; no copies of files any more). model\fbx and model\rigs hold your Model-tab exports, Blender scenes and rigs: clear them with Settings → Model → Clean Up Exports and Rigs, which shows what each one is and sends the ones you pick to the Recycle Bin. model\converted holds Blender and XPS models read through Blender; it's made again when you browse to them.
