MHO Extended Mod Manager

Manual for version . Press F1 in the app to open it, Ctrl+F here to search.

MHO Extended Mod Manager installs, orders and removes mods for Marvel Heroes Omega. It reads and writes the same mod format as MHModManager 1.0.1, so mods made for either work in both, and it adds a lot on top: a 3D preview, an editor with an icon creator, Nexus update checks, and moving a costume mod to another costume.

Getting Started

  1. Install. Run the Setup file (or unzip the ZIP) anywhere except Program Files or the game folder: the app keeps everything in a data folder next to itself. It needs the .NET 8 Desktop Runtime; Setup offers Microsoft's download if it's missing.
  2. Windows may warn you. The app isn't code-signed, so SmartScreen can say "Windows protected your PC": click More info, then Run anyway. Download it only from Nexus or the GitHub releases page, and compare the .sha256 file if you want to be sure.
  3. First start. The app finds the game through Steam (or asks you to browse to it), then asks whether you used MHModManager. If you did, it copies your mods, their order and on/off state, and the verified stock backups; your old folder isn't changed. Stop using the old manager afterwards, or the two will undo each other's changes.
  4. Use it. Tick the mods you want, order them, and press Apply Changes with the game closed.
Everything the app keeps (your library, settings, the record of what it wrote to the game, 3D views) is in data next to the exe. Keep one copy of the app: a copy somewhere else has its own data.

Install a Mod and Put It in the Game

  1. Download the mod (a .zip, .7z or .rar). Close the game.
  2. Click Install Mod (the download arrow at the top left), or drag the archive onto the window. The mod appears at the top of the list, turned off. (Mods for the older MH Texture Manager, a .json and a .tfc, are converted into ordinary mods as they're installed.)
  3. Tick its checkbox. The status line at the bottom now says how many game files will change.
  4. Click Apply Changes at the bottom right (or press Ctrl+Enter). A window lists what will be written; click Apply. When it closes, the mod is in the game.
  5. To take it out again: untick it and Apply Changes. The game's original files go back.

Remove Several Mods at Once

  1. On the Mods tab, mark the mods: Ctrl+click each one, or click the first and Shift+click the last.
  2. Click Remove Mod (the bin) or press Del.
  3. Read the warning: it lists every mod that will be removed, and Cancel is the default button, so Enter removes nothing. To keep one, Cancel and Ctrl+click it out of the selection.
  4. Click Remove N Mods. They're turned off, Apply Changes runs once, and their folders go to the Recycle Bin (you can restore them from there).

Decide Which Mod Wins

When two mods change the same file (two Storm costume mods for the same costume, say), the one higher in the list wins.

  1. Look for the colored stripe on a card's left edge: red means part of that mod loses to a higher one, amber means it only wins. Select the mod and open its Conflicts tab to see who wins what.
  2. To see every mod that shares files side by side, pick Group ▾ → Conflicts.
  3. Drag the card you want to win above the other (or select it and use ⤒ ▲ ▼ ⤓, or Ctrl+Up / Ctrl+Down).
  4. Apply Changes.

Keep a Mod's Look Near Other Players

  1. A mod with a yellow ⚠ OVERLAP pill changes a model the game also keeps in other files (a team-up's character is often also a summon or an NPC). Hover the pill to see which.
  2. Click OVERLAP (or right-click the card → Make Unique) and confirm.
  3. Apply Changes. The mod now keeps its look even when someone nearby loads the game's copy.

When sharing is what you want (a modded S.H.I.E.L.D. agent package that should also change Nick Fury's summoned agents, whose copy is in his own file): open the mod in the Editor, tick Keep Shared Paths on the right of Overview → Details, and save. The note under it says what each choice does; see Keep Shared Paths.

Group ▾ → Overlap lists every mod with an OVERLAP pill together. A model that only an enemy's power shares (a boss summoning a copy) counts too.

See OVERLAP.

Fix a Mod That Can Crash the Game

  1. A red ⚠ CRASH RISK pill on a card means a model in the mod can crash the game (an Array.h:575 error): it has more bones than another copy of the same model in the game (added bones for a cape, a dress, wings or a loincloth), or its mirror table doesn't have one entry per bone. Type is:crash in the filter to list every such mod.
  2. Click the pill. The window lists each finding and offers what fixes it: Make Unique (the mod's model gets a path of its own) and / or Fix Mirror Tables (every bone gets a mirror entry).
  3. Click the button. Only the mod's own package files change, saved like an edit; the pill goes away when nothing is left.
  4. Apply Changes. It's a good idea to let the mod's creator know too, so they can update it officially.

Models built on the Model tab are checked and fixed by Build into Mod and Save Changes. See CRASH RISK.

Mods that are fine alone can clash together. Apply Changes checks your turned-on mods as a set before it writes anything: under Checks it lists any model that would be in the game in copies with different bone counts (a crash risk), and any model two turned-on mods both changed (only one of them shows). Turn one of the mods off, or move the one you want above the other.

Watch a Hero's Powers in the 3D Preview

  1. On the Mods tab, select a costume mod. The preview in the middle shows its model in 3D (click the 3D picture in the strip if it shows a picture).
  2. At the bottom of the preview, click one of the hero's power buttons. Its animation plays with the power's effects: beams reach toward a target in front of the hero at the height they aim, missiles fly there and burst where they land, and what a power does to the one it hits (a stun, a burn, an impact) plays there.
  3. Press P to pause. The Frame slider takes the focus, so the arrow keys step through the animation one frame at a time; P again plays on from there.
  4. Turn the effects off and on with Power FXs above the buttons. Click the power again to see all the hero's animations.
  5. An effect too faint to see? Open Look ▾ (the eye) and raise Effects (10 % by default; remembered for every 3D preview).
  6. Powers with effects but no animation (procs, passives, Doctor Doom's The Will of Doom) have buttons too: their effects play over the idle (with Power FXs on). A power that changes the character's materials for a moment (Doom's force field) shows it on the model.

See Preview.

See a Hero's Forms, Transforms and Summons

  1. Open the hero's mod in the Editor and go to Powers (or select the mod on the Mods tab and use the preview's power buttons).
  2. A form: pick the power that turns it on, or one of the form's own powers. Jean Grey's Unleash the Phoenix shows her Phoenix form: her flying animations, the flaming wings and the form's flames. The form's versions of her powers have buttons of their own, named after the form (Pyrokinetic Barrier (Unleash the Phoenix)). Another power takes the form off.
  3. A transform: Rogue's Final Form, Rocket Raccoon's Mechfall and Loki's Frost Giant show the transformed character, with its own animations and props, when the power that turns it on or one of its abilities is picked (Swift Claws (Final Form), Frost Orb (Frost Giant)).
  4. A summon: a power that summons a character shows it beside the hero for the power's length, with its own arrival animation and effects: Jean Grey's Telepathic Illusion (the costume's own illusion, see-through with the game's glow), Doctor Strange's Images of Ikonn, Nick Fury's agents, Squirrel Girl's squirrels. When the mod carries the summon's model, the mod's model shows, as in game. Full Body frames the summons too.

Known: Rocket's mech suit shows above its pilot in the preview. A summon stands beside the hero; in game it appears where the power is aimed. See Watch a Hero's Powers in the 3D Preview.

Make a Costume's Icons from the 3D Model

Every costume has a store image (300×420), a portrait (herohor, 180×136) and a costume icon (40×40). You can make all three from the costume's own model.

  1. Select the mod and click Edit Mod (the pencil at the bottom left). The Editor tab opens.
  2. Open Icons, then Store Images (or Icons for the portrait and costume icon). The list on the left shows the costume's own images first.
  3. Click the image to replace on the left, then the Create from 3D tab beside Replacements.
  4. Frame the character: drag to turn, right-drag to move, the mouse wheel to zoom. The framing buttons give the usual full body, bust or head shot. Pick a pose from the animation list and a frame with the slider; press O to lay the game's original over it to line things up.
  5. Click Take Snapshot, then Use as Replacement. (Save Large PNG ▾ saves a big copy for a post instead.)
  6. Click Save Changes (the check mark at the bottom right), turn the mod on and Apply Changes.

To use a picture you made elsewhere instead: on the Replacements tab, pick the image on the left and load your .png or .dds; it's converted to the right size and format. See Icons and Create from 3D.

Change a Costume's Name or Text

  1. Open the mod in the Editor and go to Strings.
  2. Type the current text (the costume's name, say) into Find Text or ID and click Search. The Used By column says what each result belongs to (a costume's name, a hero's, an item's), so you pick the right one.
  3. Select it and click Add Selected to the Mod ↓; it appears under This Mod's Changes. Type the new text in its replacement column.
  4. Save Changes, then Apply Changes.

Wear a Mod on Another Costume or Hero

A costume mod replaces one costume. Moving it gives you a copy on another costume, so you can wear both, or puts it on a different hero altogether.

  1. Select the mod. Its header shows Costume: … ▾; click it (or right-click the card → Move to Another Costume).
  2. Pick a costume of the same hero, or Another Hero at the bottom of the list to choose a hero and then one of their costumes.
  3. The Move window shows what moves and what doesn't. Click Create Mod.
  4. The new mod "Name (on Costume)" is at the top of the list, turned on, with the original turned off. Apply Changes.

On another hero, the model and voice come along, while the target hero's animations and powers stay. See Move to Another Costume.

Recolor a Hero's Powers

  1. Open the mod in the Editor (a costume mod for that hero; save a new mod once first) and go to Powers.
  2. Pick a power in the bar of icons under the preview (hover one for its name; the view frames the whole character). Its animation shows in the preview; press ▶ to play it with its effects.
  3. Move Hue, Saturation and Brightness, or click one of the power's own colors under Colors in This Power to replace just that color (type a hex code, or use the color wheel and its eyedropper).
  4. Apply to All Powers gives the hero's other powers the same color. Save Changes, then Apply Changes.

A power that's missing from the list, or doesn't change fully in game? Add Package adds one of the game's effect packages under its file name; its color recolors the whole package, for every character that uses it (the preview doesn't show it: check it in game). See Add Package.

A power's colors change for every costume of that hero. See Power colors.

Make a Power Dark

  1. Open the mod in the Editor and go to Powers. Pick the power.
  2. Click Dark. It sets Saturation 0 %, Brightness 0 % and Opacity 500 %; move the sliders to fine-tune it (Opacity goes up to 1000 %: higher is more solid).
  3. Check the 3D preview: the effects show dark, as the game will draw them.
  4. Save Changes, then Apply Changes, and look at it in game.

What it changes: Translucent effects (energy fields, smoke) simply turn dark. Glows, beams and sparks that the game adds as light would vanish with a dark color, so Save redraws them with a copy of one of the game's translucent effect materials, keeping each effect's shape (beams keep their narrow core). Mesh effects and heat-haze distortion keep their own materials and can still fade.

See Dark powers.

Switch Off a Power's Sound, Effect or a Character's Hover

  1. Make a mod with one of the hero's packages (Packages tab → Add .UPK Files, from the game's CookedPCConsole folder: a costume, or the hero's own UC__MarvelPlayer_<Hero>_SF.upk), and save it once.
  2. Open it in the Editor and go to Powers. Pick a power, or <Hero>: Character (the Char tile) for the hero's own parts (hover, dodge …). Its Color tab recolors those parts' effects, such as the dodge's ghosts, as for a power.
  3. The Parts tab lists what it shows and plays: Settings (such as Can Transition to Hover), Attachments (props such as Invisible Woman's disc), Effects (▶ shows one in the 3D view over the idle: Dodge Effect shows the dodge's ghosts) and Sounds (▶ plays one). Untick the ones to switch off.
  4. A power's own effects play alone with ▶, on the character as the power shows it (Unleash the Phoenix: on her Phoenix form, with the wings). Pick the power again for all of them.
  5. Save Changes, then Apply Changes.

Dodge ghosts from your model: many heroes leave ghost copies of themselves when they dodge (54 of 66). The Dodge tile after Char in the power bar goes straight there (Parts, with the dodge playing; the hero's other own effects, such as level-up, get tiles of their own too). Parts shows Dodge Ghosts under the list: Make Them From This Model makes them from the mod's model, at the character's own size and where it stands: each in the hero's combat idle, leaning 10° another way (forward, back, left, right) to look like it's moving. Lean ▾ changes a ghost's lean, and the Lean slider how far they all lean (10° at first). To choose a ghost's pose, select it, pick an animation in the preview and drag Frame to the moment you want, then Use This Pose; Automatic takes that ghost back to its automatic pose. Show Pose (or a double-click on a row) takes the preview to a ghost's animation and frame. Exact Size, on the Ground (on) undoes the effect's own 1.1× size and 5-unit drop, so the ghosts stand on the ground at the character's size; Look ▾ → Ground shows the floor (a grid of hexagons, 50 units across) to check it. The preview shows the ghosts at once (▶ on Dodge Effect plays them), and the Color tab recolors them. Save writes them into the hero's package, so every costume of the hero shows them. Game's Ghosts puts the game's back.

Example: Invisible Woman's hover when she runs a while: Invisible Woman: Character → untick Can Transition to Hover. She keeps running, with no disc, hover effects or hover sound (tested in game). Her travel power (Levitating Disc) is a power of its own: its disc is the Flyingdisc attachment, its glow and sounds are its effects and sounds.

What it changes: Each part is switched off inside the game's own package (an effect's particle system, a sound's events or an attachment set to none, a setting set to false); Save puts that package in the mod as the game's copy with the change, so every costume of the hero is affected, and MHModManager can install the mod too. Tick a part again for the game's own: a package that came in only for its parts leaves the mod.

Give a Costume Another Character's Animations

  1. Open the mod in the Editor and go to Animations. Click a row to play that animation on the costume.
  2. Select the animation to change (the idle, say) and click Change Animation, or double-click the row.
  3. Pick a character and one of its animations; it plays on the costume's model so you see it before you use it. Click to use it. The row turns amber.
  4. To take many at once, Copy From a Character lists every animation with the same name as one of the costume's, ticked; Use Ticked puts them all in.
  5. Save Changes, then Apply Changes. Only this costume changes; the hero's other costumes keep their animations.

See Animations.

Give a Costume Another Voice, Shift It or Add Effects

  1. Open the mod in the Editor and go to Audio → Voice. If no lines show, use the button above the list to put the hero's voice in.
  2. Press ▶ on a line to hear it; untick a line to turn it off.
  3. Use Another Voice gives the costume a whole voice from the game (another costume's, or another hero's). Team-ups work the same way: a mod's team-up package (UC__MarvelTeamUp_…) gets the Voice tab too (list, play, turn off, shift, or replace its voice), and the Team-Ups submenu offers 44 team-ups' voices (Angel, Jessica Jones, Beta Ray Bill …) for a costume or another team-up.
  4. To make the voice higher or lower, start from Female → Male or Male → Female, adjust Pitch, Formant and Warmth while playing lines. For an effect, move the EFFECTS sliders (Reverb, Echo, Distortion, Lo-Fi, Chorus, Robot). Then click Apply to This Voice.
  5. Save Changes, then Apply Changes.

See Voice lines.

Put Your Own Model on a Costume

  1. Open the mod in the Editor and go to Model. (The first time, Settings → Model sets the folders it reads.)
  2. Under Source, choose MFF Repository and pick a character from your MFF rip, or Single Model and Browse for a Model: an FBX, OBJ, DAE (Collada), STL, Blender file (.blend) or XNALara / XPS model (.xps, .mesh, .mesh.ascii). It can be rigged with the game's bones, Mixamo's or another skeleton, or not rigged at all (it's rigged for you in Blender). An MFF character's model is recognized and read with its folder. Its textures are found beside it, in its subfolders, or in folders next to its folder (such as Textures). Or choose From the Game and pick a hero costume, team-up or NPC from the game: its model and maps are taken as the source.
  3. Under Target, pick the costume package it goes on. (While something loads or builds in the background, the ring beside the status line turns; the one in the top bar shows anything running in the app. Point at it to see what.) The preview shows your model on the hero's skeleton; play animations to check it moves well.
  4. Untick parts you don't want under Parts. When several parts share one material (a body and its clothes on one texture sheet), tick Own Material on a part to give it a material of its own: it shows on the Materials tab as <material> @ <part>, with its own maps (Replace File), game material and slot. Under the parts, The Target's Props lists the costume's own props (a belt, a weapon, a whip), which stay on whatever model is built onto it: untick one to leave it off (Save sets its mesh to none in that costume's package only; tick it again for the game's). If something bends wrongly, the Bone Map says which hero bone drives what. Materials lists each material's maps.
  5. To make the character bigger or smaller in game, move Size in Game (under Material).
  6. Click Build into Mod, then Save Changes, then turn the mod on and Apply Changes. (If you change something and forget to build, leaving the Model tab or Save Changes asks: Build Now / Build and Save.)

See Model.

Make a Character Bigger or Smaller

  1. Open the mod in the Editor and go to Model. Under Target, the mod's character is picked already (with several, the first by name); pick another of its packages, or From the Game to add one. Filtering the game's list shows heroes first, then team-ups, then NPCs and the rest.
  2. Move Size in Game (5–400 %; double-click for 100 %). The preview shows the new size; Compare shows the game's.
  3. Leave Match Steps to Size on so the feet don't slide: a bigger character's run and walk play slower, a smaller one's faster.
  4. Click Build into Mod. Without a source picked, it writes only the size (a model built in earlier stays). Then Save Changes and Apply Changes.

A costume that uses its hero's model has no size of its own: the log says to size the hero's base package instead, which sizes every costume of the hero that doesn't set its own. See Model.

Put a Model on an NPC, Enemy or Team-Up

  1. On the Model tab, open From the Game under Target and pick a team-up, an NPC or one of Enemies and Bosses (the ones with the heroes' skeleton). It's added to the mod.
  2. Pick a source as for a costume. The preview plays that character's own animations.
  3. Any other package with a character in it (a pet, a vehicle, another mod's package) works too: Browse for a Package at the end of the Target list. It has to be named like a game package, since the mod replaces that file; picked from the game folder, the game's stock copy is used. When a package holds several characters (a hero's base package can hold props or another hero's model), Model ▾ under the Target filter picks the one the model is fitted to and replaces; Automatic takes the costume's own model.
  4. Build into Mod, Save Changes, Apply Changes. The new model shows wherever the game uses that character, with its own powers.
  5. To take a target off the list again, right-click it → Remove (or select it and press Delete). One the Model tab added leaves the mod, with its build. For one of the mod's own packages you choose: Restore the Mod's Copy takes the model off, Remove From the Mod takes the package out. Cancel in the editor brings it all back.

Team-ups and many NPCs store their animations so that they set every bone's position; the build changes them to work like a hero's, so the new model keeps its own shape (the log's anim: line).

Give a Model a Moving Coat, Dress, Tail or Wings

  1. On the Model tab, pick a source whose model has the part (a long coat, a dress or skirt, loincloth strips, a tail, chains or wings) and a target hero that has no bones for it.
  2. On the Parts tab, open Add Rigs ▾ and pick the kind and a donor number: Coat 1 moves like Blade's coat, Dress 1 like Angela's, Tail 1 like Nightcrawler's, Wings 1 like Angel's (point at an item for the others). Several kinds can be on at once; the button shows them.
  3. The preview shows the part moving in every animation; the log says how many of the model's strips ride the added bones (4 model chain(s) ride Coat 1). None means the model's part is too far from them: try another donor.
  4. Build into Mod, Save Changes, Apply Changes. The build copies the hero's animations into the mod with the added motion (a base package as the target).
  5. A kind the hero already has bones for shows as Hero's Own and stays as it is. Remove All takes every added rig off.

Swap a Costume's Weapon or Shield

  1. On the Model tab, pick the costume (or hero) package under Target, and an MFF character that carries the weapon under Source (US Agent for his shield).
  2. Open Model ▾ above the Target list and pick the prop: props are marked Prop (captainamerica_shield_avengers · Prop).
  3. Under Parts, the part most like the prop is ticked on its own (US Agent's shield). Tick another part to use it instead.
  4. Build into Mod. The part is laid over the game's prop: centered, turned onto its axes, scaled to its size and held on the same bone. A round shield can come out turned in its own plane.
  5. To give the character a new body too, pick it under Model ▾ and build again: each build keeps the other's. Then Save Changes and Apply Changes; the Mods tab's 3D preview shows the prop in the character's hands with Props on.

Recolor or Hide a Character's Own Effects

  1. The mod needs the character's package (the Model tab's From the Game adds it, or a model built onto it).
  2. Go to Powers. At the end of the list: <Name>: Own Effects (its glows and trails, such as the Sinister clones' red glow), then that character's own powers.
  3. Pick one; the 3D view plays it. Move Hue, Saturation, Brightness, or click a color under Colors in This Power to replace it.
  4. To make the effect disappear, move Opacity down; at 0 % it's gone, and a hologram team-up (the Danger Room Wolverine) shows its own materials instead.
  5. If the entry says the character is built on another one's package (the Sinister Medal pets), click Add It to This Mod and recolor that one.
  6. Save Changes, Apply Changes.

Heroes too: a hero whose own package carries always-on effects (Ghost Rider's flaming skull) has <Hero>: Own Effects in a costume mod's Powers list. A costume that takes them from its hero (Ghost Rider's Modern VU) shows the hero's entry; Save adds the hero's package (the game's copy) with its color, and the color reaches every costume of the hero that uses those effects.

See Power colors.

Edit the Model, an Animation or a Texture in Blender

  1. On the Model tab, with a source and target picked: Full Export ▾ → Open in Blender (everything), or Single Animation ▾ for just the animation shown. Blender opens a scene with the model and the hero's animations, as this mod plays them: an animation changed in the Animations tab plays and exports as changed (pick it in the preview, then Single Animation ▾ to fix weights for that move).
  2. Edit: the mesh and its weights (Weight Paint), bones (Edit Mode: their joints move, they keep their direction), an animation's keys, or the textures (Texture Paint: horns, logos, scars).
  3. Press Ctrl+S in Blender. The Model tab's log says what it took in, and its status turns green. Painted textures come in as the material's maps in the Materials tab (Back to Automatic undoes one). In a scene opened before 0.37.178, also save the painted image (Image → Save).
  4. Back in the app: Build into Mod, Save Changes, Apply Changes.

For a model that came without bones, its rig is in Full Export ▾ → Open the Rig in Blender: fix its weights there, and each Ctrl+S re-rigs the model.

Edit a Model's Textures in Your Image Editor

  1. The first time: Settings → Model → Choose Image Editor. GIMP, Photoshop, Corel PHOTO-PAINT, Affinity Photo, Krita and Paint.NET are found when installed; Another Program takes any other.
  2. Open the mod in the Editor, go to Model, pick the target package, then the Materials tab. With a source picked, it lists the maps the build will use; with no source, the textures of the model already in the package (one you built earlier, or the game's). Textures the model takes from its hero's base package (Jean Grey's Phoenix wings) are listed too, marked with that package: changing one asks first, then adds that package to the mod, so every costume of the hero that uses the texture shows the change.
  3. Pick a row: click it, or Ctrl+click that part of the model in the preview. Double-click shows it large.
  4. Click the pencil (Edit in Image Editor), right-click the row, or use Edit in … in the large view. The map opens in your editor as a PNG.
  5. Paint, then save over that PNG (in GIMP: Ctrl+E; Ctrl+S only saves GIMP's own .xcf). About a second later the preview shows it. Save as often as you like.
  6. Build into Mod (with a source), then Save Changes and Apply Changes.

While something loads or builds, the ring beside the Model tab's status line turns; point at it to see what's running.

Change a Model's Colors Without an Image Editor

  1. Open the mod in the Editor, go to Model, pick the target package, then the Materials tab.
  2. Pick a material's Color row and click the sun (Adjust Colors), or right-click the row.
  3. Move Hue, Saturation and Brightness, or the Levels, and watch the map before and after side by side. ↺ resets.
  4. Click ✓. With a source picked, the build uses an adjusted copy (your file isn't changed; Back to Automatic clears it). With no source, the texture in the mod's package is changed.
  5. Build into Mod (with a source), then Save Changes and Apply Changes.

Choose How Each Part of a Model Looks in Game

  1. Open the mod in the Editor, go to Model, pick a source and the target package, then the Materials tab.
  2. Several parts on one texture sheet that should look different (skin and armor)? Under Parts, tick Own Material on a part: it gets a material of its own, <material> @ <part>.
  3. Pick a material and choose its Game Material ▾: Automatic, Cloth and Skin, Metal, Glow or The Costume's Own. Preview Shows picks which maps the preview draws.
  4. The costume's effects (a force field, a glow) keep material slots by number: use Slot Up / Slot Down so each lands on the right part (the note above the list says which).
  5. Bumps that look flat, or none at all? Right-click the material's Color or Normal row → Generate Normal Map and pick a strength (Soft, Medium, Strong, or Medium, Dark Is Raised). The preview shows it at once; Undo takes it back.

The Mod List

Each mod is a card: its picture (the hero portrait or costume icon it replaces, or the game's own), its name, author, tags, the P T S A badges (Packages, Textures, Strings, Audio) and, on the right, whether it's on and either what it changes or the costume it's for.

  • On / off: the checkbox on the card. Nothing reaches the game until Apply Changes.
  • Priority: the higher mod wins when two change the same file. Drag a card, or use ⤒ ▲ ▼ ⤓ above the list (Ctrl+Up / Ctrl+Down one step, Ctrl+Home / Ctrl+End to the top or bottom).
  • Several at once: Shift+click selects a range, Ctrl+click adds or removes one (Shift+Up / Shift+Down too). Then a checkbox of one of them, or Space, turns them all on or off; dragging one of them, or the priority buttons and keys, moves them together in their order. Esc or a plain click goes back to one. Each of these is one Undo step.
  • Padlocks: a mod at the top or bottom can be locked there (the padlock under its checkbox). Several mods can be locked in a row at each end. A locked mod moves only among the mods locked at the same end (drag, the arrows or Ctrl+arrows reorder them there); other mods can't pass the locks, and new mods land inside them.
  • Conflicts: a stripe on the card's left edge. Red: part of this mod loses to a higher one. Amber: it only wins. The selected mod's partners are outlined, and the Conflicts tab says who wins what.
  • Nexus: an orange N on the picture means the mod is linked to a Nexus page, a green ↑ and an ↑ UPDATE pill mean Nexus has a newer version.
  • ⚠ OVERLAP (a yellow warning pill): the mod changes a model, or a power's effect or texture, that other game files also carry under the same name. Many characters are in several files: Jessica Jones is in her team-up, her summon (Luke Cage's talent) and the Avengers Tower NPC; Angel is in his team-up and in Cyclops' own file. The game uses whichever copy loads first, so near other players, their summons and team-ups, or hub NPCs, the mod can show the game's look instead of its own. Click the pill (or right-click the card → Make Unique) to give the mod's copy names of its own: only the mod's own package files change (saved like an edit), textures the game streams keep their names, and the mod still installs in MHModManager. Then Apply Changes. A mod that ships every file carrying the model doesn't get the pill. Moving a costume to another hero, and saving in the editor, do this by itself. The hero's own copies stay shared: a hero's illusions, afterimages and summons (Jean Grey's and Emma Frost's illusions, Doctor Strange's projections, Nick Fury's agents) carry the costume's model too, and sharing its path is what shows them in the mod's look. So do other heroes' summons of the same character (Cyclops' Call Jean summons Jean Grey in her costume): a Jean Grey mod shows on that summon too, and her own illusions keep the mod's model. A boss or enemy that carries the model is still renamed away. Saving also fits those summons to the mod's model: an illusion's see-through material is set on every material slot of the mod's model, and the summon's size changes when the mod changes the character's size (the game's own proportions stay: Jean Grey's illusions are a little bigger than her in the game too); those summons' packages are added to the mod. A mod made unique before these rules (version 0.50.18) is put right by opening it in the Editor and saving: what today's rules keep shared gets its game name back first. Only a model with more bones than the game's is renamed even there, because sharing it with a copy that has fewer bones can crash the game. Before it does anything, the Make Unique window says what it changes: which characters keep the game's look afterwards, and which stay shared. Undo Make Unique (right-click the card) puts the mod's packages back as they were before, as long as nothing changed them since (a Model build, a color, an update), and ticks Keep Shared Paths so saving doesn't rename them again. A mod that shares its paths on purpose shows a blue SHARED pill instead of OVERLAP: hover it for what's shared, click it for what that means, or to make the mod unique after all. Mods made unique before version 0.37.273 have no copy to go back to: restore the old folder from the Recycle Bin, or reinstall the mod's file. The same pill warns about a power package only enemies use (no hero power uses its look: a Taskmaster costume mod that replaced the Taskmaster boss's Shield Toss made the boss throw the costume's shield): click it, or right-click → Remove Enemy-Only Packages, and choose Remove from This Mod or Remove in a Copy (the original stays, so you can switch back).
  • Keep Shared Paths (Editor → Overview → Details, on the right): sometimes sharing is what you want. A modded S.H.I.E.L.D. agent package also changed Nick Fury's summoned agents, because his summon carries a copy of the same model in his own file; Make Unique took that away. With Keep Shared Paths on, Save leaves the mod's paths as the game's and the mod gets no OVERLAP warning (the choice travels with the mod). The impact: wherever another file carries the same path, the game shows whichever copy loads first, so your look can spread to those characters, or the game's look can show instead of yours near other players and in hubs. Off (the default) is the safer choice: your look stays yours, and characters sharing the path from other files keep the game's look. A CRASH RISK warning still shows either way, and its window still offers Make Unique.
  • ⚠ CRASH RISK (a red warning pill): a model in the mod can crash the game. The game keeps a few lookup tables per model, one entry per bone, and crashes (an Array.h:575 error) when it reads past the end of one. Two things cause it: the mod's model has more bones than another copy of the same model in another game file (added bones for a cape, a dress, wings or a loincloth on a character who is also a summon, an illusion, a team-up or an NPC: the copy loaded first decides the table, and a shorter one crashes the bigger model when both are around), or the model's mirror table doesn't have one entry per bone. Click the pill for every finding: Fix Mirror Tables gives every bone a mirror entry (an added left bone mirrors its right partner, others themselves), and when another copy is the cause, Make Unique fixes it (the mod's model gets a name of its own, so it gets its own tables). Both change only the mod's own package files, saved like an edit. A third cause is a costume moved by an older version: textures whose larger sizes stream from the game's texture cache got a new path the cache doesn't know, and the game hangs, then crashes, when it needs them (Emma Frost's Diamond Form). Move the original mod again to rebuild the copy. Added bones on a model no other file carries are fine. The Model tab's Build into Mod fixes the mirror table of the model it builds by itself and lists the checks in its log, and Save Changes makes the model unique by itself. These checks follow what the MH Mesh Checker (another modder's tool) found.
  • Moved costumes: a mod made with Move to Another Costume ends in (on Classic) in amber: that part is the app's, not the mod's name.
  • All turns every mod the list shows on (or off, if they're all on).
  • Undo / Redo (Ctrl+Z / Ctrl+Y) step back through list changes: on/off, order, locks, tags, notes. They don't touch the game: to take a mod's changes out of the game, turn it off and Apply Changes, which puts the originals back.

Apply Changes

Apply makes the game match your list. It's the only thing that writes into the game folder, and it needs the game closed.

  • For every package a mod names, the highest enabled mod's copy goes in; if none is on, the game's original goes back.
  • Icons, store images and strings are rebuilt from the game's originals with the winning replacements, so turning a mod off really takes its icons out.
  • Sound packs are built into the game's sound files from their originals.
  • Every file is written to a temporary copy, checked, and only then swapped in, with an undo snapshot.

The status line says how many files are waiting ("4 File(s) to Change"). Click it, or press Apply Changes (Ctrl+Enter), to see the plan first; nothing is written until you press Apply in that window. When everything went well the window just closes. If something stops, it stays open with the log: files written before the stop were checked and stay; nothing after it changed.

Checks. The top of the Apply window lists anything unexpected: files that can't be changed because there's no clean original of them, and game files changed by something other than this app (another tool, a mod folder deleted by hand) that Apply leaves as they are. When a file has no clean copy, it suggests Settings → Clean Game Files Folder and explains how to get a clean copy from Steam: verify the game's files in Steam (which takes all mods out of the game folder), copy the CookedPCConsole folder somewhere outside the game folder, choose that copy as the clean folder, then Apply Changes again to put your mods back.

A game file this app wrote earlier that no mod names any more (a mod that dropped a package when it was edited or updated, or a mod folder deleted by hand) goes back to the game's original, the same as when a mod is turned off.

Apply only puts back files that are still what it last wrote or last saw there (it keeps a small record of each game file it manages). If another program (a freecam installer, Package Modifier) or you by hand changed a game file since, even with a mod's own files, Apply leaves it alone, even when a turned-off mod names that file, and lists it under "Left as they are". Turning a mod off still restores the files this app put in for it.

Review Changed Files (in the Apply window when there are any, or Settings → Changed Game Files) lists the game files changed outside this app. Select one or more, then Keep as a Mod (they're copied into one new mod in your list, turned on and at the bottom, so you see them and can turn them off later; the game isn't changed) or Restore to Original (the game's own files go back, from the clean originals, with a .bak made first if there's none; the game must be closed). Files you don't act on stay as they are.

Originals: the app only trusts a copy of a game file as "original" if it matches the stock checksum list (every one of the game's 15,250 packages). Files that were already modded before and have no clean copy are "left as they are" and listed in the plan.

Installing, Updating and Exporting

  • Install Mod (or drag an archive onto the window) takes a .zip, .7z, .rar or a folder. An archive can hold several mods. New mods go to the top of the list, turned off: tick them, then Apply Changes. A mod made for the older MH Texture Manager (a .json and a .tfc instead of a manifest.json) is converted as it's installed: its textures go into the game packages that use them (from the game's stock copies, the new mip levels stored in the package), so it becomes an ordinary mod that turns on and off like any other and leaves the game's texture caches alone. Its name and version come from the Nexus file name when there is one, and its author from that mod's Nexus page (public information; only the page's number is sent; without a connection the author is left as Unknown).
  • Updating: installing a mod whose name you already have asks to replace it. Right-click a card → Update from a File replaces that mod with an archive's mod under any name. Either way the mod keeps its place, on/off, lock, tags and note.
  • Duplicate: right-click a card → Duplicate makes a copy of the mod under a new name (it asks for one: "Name (Copy)" to start): every file comes along, the Model tab's work and the editor's settings too, and your tags, note and picture picks. The copy goes at the top of the list, off, so you can experiment from it while the original stays as it is (turn one on at a time: both change the same game files).
  • Export to ZIP saves the mod as Name - vVersion.zip; a mod with a saved post (Create Post → Save to Mod) also gets its post and images in a folder beside it. If the mod uses features MHModManager doesn't know, you can export a legacy copy without them.

Removing a Mod

Remove Mod (or Del) tells you what will happen and asks once:

  1. the mod is turned off (if it's on);
  2. Apply Changes runs, so the game gets its original files back (other changes waiting in your list are applied too);
  3. its folder goes to the Recycle Bin.

Several at once: mark them first (Ctrl+click or Shift+click), then Remove Mod or Del. A warning in red lists every mod that will be removed, and Cancel is the default button, so pressing Enter removes nothing. They're turned off together, Apply Changes runs once, and their folders go to the Recycle Bin. If Apply stops, none of them are removed.

The game must be closed. If Apply stops, the mod isn't removed: it stays in the list, turned off, and the log shows why.

Move to Another Costume

A costume mod made for one costume can be moved onto another costume of the same hero, for example Unworthy Thor (made for Age of Ultron) onto Thor Classic, so you can wear both, or onto a costume of another hero (below).

  1. Select the mod. Its card and header show the costume it's for (only mods for a single costume can move).
  2. Click Costume: … ▾ in the header, or right-click the card → Move to Another Costume, and pick a costume. The list shows each costume's store image and whether other mods already use it; the hero's default costume is marked Default in green.
  3. The Move window shows what moves (the model, materials, animations, weapon or prop, the costume icon, portrait, store image, the costume's name and other text the mod changes, and its sound pack), what's left out, and other mods for that costume.
  4. Press Create Mod. The new mod, "Name (on Costume)", goes to the top of the list; with Turn the new mod on and … off ticked (the default) it's on and the original is off. Then Apply Changes.

The original mod isn't changed. Moving again to a costume you've already moved to selects that mod instead.

The costume icon, portrait and store image must be the game's sizes (40×40, 180×136, 300×420). An image of another size is resized for the move: scaled to fill the frame and centred, so it isn't stretched (what doesn't fit is trimmed), and a message lists what was resized and from which size.

To Another Hero

At the bottom of the costume list, Another Hero opens a picker: the heroes with their portraits (type in Filter to narrow them), then the chosen hero's costumes with their store images (the default in green). The Move window then shows what moves: the model with its materials and textures goes into that costume's package, and the costume icon, portrait, store image and name follow. The voice moves too: the costume's voice set (death, level up, hits, banter, mission lines …) is copied with its sound events, so the target hero's powers play the source's lines: the mod's own voice lines (with its sound pack) if it has them, otherwise the source hero's stock voice. What stays the target hero's: the animations and powers; parts of the model the target's skeleton doesn't move (hair, a cape) stay still. The new mod is "Name (on Storm Modern)": amber for another hero, teal for another costume of the same hero.

The voice moves too. Where the moved voice has no line for a situation the target hero has (a team-up's voice has no "can't do that yet", no death line …), that situation is turned off, so the target hero's own line doesn't play there. The Editor's Audio → Voice tab lists those lines as Not in This Voice; they can't be turned on, since their sounds aren't in the mod.

Team-ups work the same way, in both directions: a team-up mod (Rescue, say) can move onto a hero's costume or another team-up, and a costume mod can move onto a team-up. In the picker, all team-ups are under the Team-Ups tile. The moved model gets the target's sockets it lacks (where effects attach), and the sockets both have are turned to face the target's way (so a beam fires straight ahead); its animations and powers stay the target's.

Capes and coats simulated with APEX cloth move along with the model, together with the model's own physics setup (the cloth needs it). A few models can't move to another hero yet, for example ones with an animated material. The Move window says so.

Sound packs come along when every sound they play belongs to the costume (as with Miles Morales' voice pack). If the original and its moved copy are both on, the pack is only added once.

How it works: the game finds a costume by its class name and its icons by name, so the moved package is the mod's own package with the costume's class renamed to the target's, the model and materials given their own names (so they can't mix with the original costume's), and the target costume's package ID. Textures the game streams from its texture caches keep their names, as the caches find them by name. A costume that lives in a hero's main package (for example Vision Classic, or a mod that replaces Star-Lord's main package) can't be a target, but it can be moved from: its model is copied into the target costume's own package instead, as for a move to another hero.

Power Colors

The editor's Powers tab recolors the hero's powers. Pick a power in the bar of icons under the 3D preview (hover one for its name; its own effects, parts and added packages follow after a gap). Its animation shows in the preview, paused: press ▶ to play it with its effects, Esc stops it) and turn Hue (around the color wheel), Saturation (0 % is grey) and Brightness; the preview shows the colors at once. Opacity fades the power's effects: 100 % as the game has it, lower makes them see-through, and 0 % switches its emitters off so nothing draws. Use it rather than Brightness to make an effect disappear: smoke, dust and gas are drawn by their transparency, so a darker color only turns them into a dark cloud. Above 100 % (up to 1000 %), Opacity makes the effects more solid: their particles' and effect textures' transparency is multiplied.

Dark powers: the Dark button sets Saturation 0 %, Brightness 0 % and Opacity 500 % (the value that looked right in game on Nova's Magneton Pulsar); the sliders fine-tune it. Translucent effects (energy fields, smoke, dust) simply turn dark. Most glows, sparks and beams are additive: the game adds their light to the scene, so a dark color would add nothing and they would vanish. With a dark color (Brightness 25 % or less), Save therefore draws each additive sprite, beam or trail with a copy of one of the game's translucent effect materials, keeping the effect's own shape, so it darkens too. The impact: mesh effects and distortion (heat haze) keep their own materials, so a few parts of a power can still fade instead of darkening; the 3D preview doesn't show the swapped materials. Check the result in game.

Switching powers keeps the Frame slider's place: the next power opens at the same point of its animation (halfway stays halfway), so you can compare powers at the same moment.

Powers the game keeps under one name in several versions (Iron Man's Unibeam and its talent-upgraded version, Thor's Ragnarok leap and strike) are one entry, and its color goes into every version's packages.

Add Package (beside Apply to All Powers): adds one of the game's effect packages (a UC__Power… file, or a projectile, hotspot or condition effect) to the end of the power bar under its file name, for a power that isn't listed or doesn't change fully. Its color recolors everything in that package, and Save puts the package in the mod. The impact: every hero, team-up or enemy power that uses the package changes too, and the 3D preview doesn't show the color (check it in the game). The Game's Colors and Save take it out again. A character's own package can't be added here: add it on the Packages tab, and its effects show as an Own Effects entry, which keeps its model.

The list has every power the hero's avatar names: those with an animation, the travel power, and also procs, passives and talents that have effects of their own but no animation (Captain Marvel's Radiant Cascade glows during her other attacks). Those play nothing in the preview; their colors show in the game during the powers that set them off.

Change single colors: under the presets, Colors in This Power shows the colors the power really uses (read from its particles, materials and effect textures, the most used first; hover one for its hex code and where it's used). Click one to replace just that color: a row appears with the new color as a hex code (#RRGGBB, for example #20FF40) and a swatch of it. Type a hex, or click the new color's swatch for a color wheel (hue around, strength toward the edge, and a Brightness slider) with an Eyedropper: press it and drag onto any color on the screen (the 3D view, a reference picture in another window), then release to take that color. Under the wheel, Recent keeps your five latest colors (on this PC, for every mod; click one to use it), and Reset takes the color back to the power's own. Each part of the power keeps its own brightness, so a glowing core stays brighter than a faint trail; a darker hex makes that color dimmer too. Range sets how close a color has to be to change with it: small for only that exact color, larger for similar shades (some powers use several close blues). × removes a replacement. You can replace several colors, and use the sliders as well (the replacements come first, then the shift). Game's Colors removes both.

NPCs, enemies and team-ups: when the mod holds an NPC, enemy or team-up package (one the Model tab built onto, for example), or a hero's audio package (Jean Grey's holds her Phoenix form's model, flames and wings), the list ends with <Name>: Own Effects: the effects that package carries itself, such as the Sinister clones' red glow and eye trails. They're recolored the same way (sliders, presets, or one color replaced). The package keeps the model the Model tab built into it, and a copy of it as it was before the recolor stays with the mod, so the color can change or go back to the game's at any time. Picking the entry plays the character's idle in the 3D view with those effects on it, in the colors and opacity you set. A team-up drawn with a hologram material (the Danger Room Wolverine) shows as a cyan glow there; at Opacity 0 % the hologram comes off and the character's own materials show, in the preview and in the saved package. Under each Own Effects entry come that character's own powers, read from the game data (the attacks its AI uses: Black Cat Boss's Punch Flurry and Spinning Roundhouse Kick, the Cyclops clone's eye beam …). They're recolored like a hero's power, play on the character in the 3D view, and the line under the colors names anyone else they'd change (the Wolverine clone's claws use Wolverine's own basic attack). Some characters are built on another one: the Sinister Medal pets (…CloneWolverineMedal_SF) extend the mob clones (…CloneWolverine_SF), so their model and most of their effects, the red glow included, are in the clone's package. Their entry then says where, and Add It to This Mod adds that package (the game's copy) and selects its Own Effects to recolor.

Heroes: a hero's or costume's package gets an Own Effects entry too when it has always-on effects of its own: the particle effects its attachments keep on the character. Ghost Rider's flaming skull is one: two flame effects on his head and neck (no material setting reaches them), and the skull's orange flame light. Only those change: his powers, dodge and death effects, body and bike stay as they are. Recolor them with the sliders or a preset, or set Opacity 0 % to hide the flame. His base package (UC__MarvelPlayer_GhostRider_SF) carries the flame for his costumes that use it (Alejandra Blaze has her own copy in her costume's package): a costume mod such as ModernVU shows Ghost Rider: Own Effects straight away (the costume has no flame of its own), and when you set a color, Save adds the base package to the mod (the game's copy) with it.

Presets: five swatches under the sliders, beside Game's Colors, Dark, Apply to All Powers and Add Package. Right-click one to store the sliders there; click it to use it on the selected power. They're kept on this PC for every mod.

On Save Changes, each colored power's own game files are recolored: its particles, effect textures and material colors, in the power's package and those of what it sets off (missiles, hotspots, conditions, pets and summons; Thor's Rolling Thunder: 6 packages). Effects many heroes share (knockdown, slow, taunt ...) are left as they are. When a few others use the same effects (Beta Ray Bill's team-up copy of Thor's), they change too: the tab names them under the presets. They become ordinary packages of the mod, so Apply Changes puts them in the game like any other, and MHModManager can install the mod too. Nothing on the server changes.

A color changes the power for every costume of that hero, for anyone using the mod: the files are the game's own power packages. Two mods that recolor the same power conflict like any two mods with the same package (the one higher in the list wins). A few effect textures stored uncompressed keep their colors.

Animations

The Editor's Animations tab lists every animation a costume plays (idle, run, emotes, attacks, power animations …), the power each belongs to, and where it comes from: the hero's own set, the costume's own, or shared ones. A costume's model lists animation sets, and a name in a later set replaces the same name in an earlier one; that's how some stock costumes have their own idle or emotes. A hero with forms (Jean Grey's Phoenix) also has a set per form, which the form switches to: its animations are listed after the others, marked Form in From, with the form's powers in the Power column (they share names with the normal ones). They can't be changed yet. Click a row to play it in the 3D view.

Change Animation (or double-click a row) plays another animation in its place. For a costume moved from another character, the window offers the Source (the character the model came from) and the Target (this costume as the game has it) first, each at the animation of the same name; any hero, team-up or other mod follows, with the same name first and every other animation below. Picking one plays it on the costume's model before you use it. Only the costume's own package changes: the hero and the hero's other costumes keep their animations. Changed rows are amber; Back to the Original undoes one. Copy From a Character does many at once: pick a character and every one of its animations with the same name as one of the costume's is listed, ticked (Find narrows them by name or kind, such as Emote or Movement; Tick All / Tick None act on what's shown); Use Ticked puts them all in. Picking the Target there undoes the ticked ones. Changes are saved with the mod.

Props (under the list) gives the costume another character's prop as well as its own: Add a Prop, pick a Hero and one of their props (Thor's hammer for Captain America, with his shield staying on his arm). The costume holds it in every animation, on the bone its own character holds it on, in its own weapon slot; pair it with that character's idles and fidgets (Copy From a Character) so the hand pose fits. Size, Move X / Y / Z (along the global axes of the 3D view's axis gizmo, as the prop is held in the frame shown) and Turn X / Y / Z fit it; Look ▾ → Prop Pivots shows where it's held. Pivot on the Hand holds it in the animations taken from another character the way that character holds it: in the hand where theirs is held, swinging where theirs swings (Thor's fidget02 swings the hammer by its strap). It's worked out from that character's own animation, frame by frame, and baked into the copies; without it, Thor's animations move his hammer bone to where it is on Thor and the hammer floats by Cap's head. In This Animation (beside the fit, for the animation selected in the list) moves and turns the prop further in that animation only, for a pose that wants it elsewhere: Move X / Y / Z along the global axes (the axis gizmo's) and Turn X / Y / Z about them, around the point it hangs on, the same in every frame of that animation; Copy From starts from another animation's adjustment, Reset takes it off. It's baked into that animation (it needs Pivot on the Hand and an animation from another character, a Changed row). Remove takes it off again. The prop is copied into the costume's package, so the old manager installs it too.

Model

The Editor's Model tab puts a model of your own on one of the mod's character packages: a Marvel Future Fight character from your own MFF rip, or an FBX file from Blender or anywhere else. The model is fitted to the hero's skeleton, so the hero's own animations, powers and props play on it. The tab has three columns: Source (the model), the Preview, and Target (the package it goes on). Above them, the folders it reads: MFF (your rip), GAME and STOCK (a clean copy of the game's packages); point at one for the full path, click to open it. They're set in Settings → Model.

Source and Target

A small screen? On the Mods tab, drag the dividers beside the mod list and between the preview and the details (double-click the second one for the automatic width). Here, drag the thin dividers between Source, Preview and Target, between Target's list and its Parts / Bone Map / Materials tabs, and above the log, to give a panel more room. Click a heading (SOURCE, TARGET, MATERIAL, SIZE IN GAME, LOG) to fold that panel away or back. Sizes and folds are remembered. Settings → UI Scale (80–150 %) makes the whole app's text and controls smaller or larger, from the next start.

Source: MFF Repository (the characters in your MFF repository folder, each with its uniforms; Characters Only leaves out props) or Single Model: one model file (Browse for a Model: FBX, OBJ, DAE, STL, .blend, or XPS / XNALara .xps, .mesh and .mesh.ascii), with the ones you've used listed below; or From the Game (the default, for Target too; the kind you pick and the Target list you switch to are remembered; in both lists a • after a name marks the hero's default costume, as the game data has it: after reworks and visual updates that's often not the package named Base or Classic): a hero costume, team-up, NPC or enemy from the game (the same list as the target's From the Game). Its model is read from the game's stock copy with its color, normal, spec and glow maps (written once as an FBX with the game's bones in data\model\game) and fitted onto the target like an FBX with MHO bones: bones the target doesn't have (a cape's, a coat's) move with their nearest parent. A .blend or XPS file is read through Blender: it makes an FBX of it once (until the file changes), with its armature, weights and textures; an STL has no textures or UVs, so it builds gray. An MFF character's model (its .fbx, .dae or .obj, rigged with MFF's Bip001 bones) is recognized and read as that MFF character, with its folder's textures. Target lists the mod's packages that hold a character (costumes, team-ups, NPCs, pets …). From the Game adds another package to the mod: a hero or costume, a team-up, or one of the game's NPCs and Enemies and Bosses (the 672 with the same humanoid skeleton as the heroes, such as Black Cat Boss, Bullseye Boss or the Civil War bosses). Browse for a Package adds any other .upk with a character in it, named like a game package (from the game folder, the game's stock copy is used). When a package holds several characters, Model ▾ picks the one the model is fitted to and replaces. It also lists a costume's props (Captain America's shield, Thor's hammer, guns and blades): pick one, and an MFF character's part takes its place instead of the body. The part most like the prop is ticked under Parts (US Agent's shield for Cap's; tick another to use it), laid over the game's prop, turned onto its axes, scaled to its size and held on the same bone; the Materials tab works on it as on a body. The game moves the same prop in every animation and power, so the new one is held, carried on the back and thrown where the old one was (see it on the Mods tab's 3D preview with Props on). A costume that shows its hero's model instead of one of its own (Captain America Avengers, Carnage Classic, Venom Classic, Thing Classic, Rogue Modern, Spider-Man Big Time …) works as a target too: the costume gets a copy of its hero's model under its own name, the new model is built onto that, and the hero's other costumes keep the shared one. Body and prop are built one after the other (pick the character, Build into Mod, then the prop, Build into Mod): each build keeps the other's. A round shield can come out turned in its own plane; for now a prop is built from an MFF character only. Right-click a target → Remove (or Delete) takes it off the list: one the tab added leaves the mod with its build, and one of the mod's own packages can get its own copy back or leave the mod (Cancel in the editor brings it back). A model built onto an NPC or enemy shows wherever the game uses that character, with its own animations and powers. Team-ups and some NPCs have animations that set every bone's position (player heroes' only turn the bones), which would pull a new model's arms and shoulders back to the old model's proportions; the build makes them turn the bones like a hero's, so the new model keeps its own shape (the build log's anim: line says so). A single model's textures are looked for in its own folder and two levels of subfolders, then in the folders beside it (such as a Textures folder next to the model's folder), by the material's name or the file names the FBX stores; then where the FBX says the file is (any folder on disk). Textures embedded in the FBX (Blender's Embed Textures) are read too (PNG, JPG and BMP; TGA and DDS aren't read). With no source picked, the preview shows the target's own model. Build From chooses what a build starts from: Before the Model (the default: the mod's package as it was before the tab built onto it, so the mod's other changes in it stay, and building again replaces the earlier build) or The Game's Stock.

An FBX can be:

  • Rigged with MHO bones (g_ names, as Full Export writes them): used as it is.
  • Rigged with other bone names (Mixamo, or other skeletons): the bones are matched to the hero's by name, or guessed from the skeleton's shape. The Bone Map shows the FBX's own names, guessed pairs in amber.
  • Rigged with a skeleton the tool doesn't know (not MHO names, and nothing it can match or guess: a few bones, a prop rig): its bones are left out and it's treated as not rigged (below); the log says so.
  • Not rigged (a mesh only): it's stood up and turned to face front, scaled to the hero's height, and rigged in Blender with automatic weights (Blender is needed; it runs in the background on your own startup scene). Face, hair and palm bones are left out of the weighting, and everything above the neck goes to the head. Full Export ▾ → Open the Rig in Blender opens the rig to fix weights by hand: each Ctrl+S there reloads the preview. Rig Again starts over.

Parts and Bone Map

Parts: tick the parts of the model to use (Default Parts goes back to the importer's choice). Weapons, effects and other props are listed unticked (kind Prop), also pieces cut out of a body part because they hang on an MFF weapon bone (Blade's swords, Red She-Hulk's weapon: "· BoneW"); tick one to build it into the body. Smooth (Subdivide) rounds off older low-poly models. Add Rigs ▾ gives a hero moving parts it has no bones for: a Cape, long Hair (1–3, or Mega Hair stretched to the model's own hair length), a Coat, a Dress, a Loincloth, a Tail, Chains or Wings. Each kind has its own list (None, then numbered donors); several kinds can be on at once, and the button shows what's added. Bones are added so the model's own strips, strands or tail ride them, and every animation gets motion matched from a hero whose part of that kind is hand-animated (Coat 1 and 2: Blade's and Nick Fury's; Dress 1–3: Angela's, Emma Frost's, Black Cat's; Loincloth 1–3: Iron Fist's, Scarlet Witch's, Doctor Strange's; Tail 1 and 2: Nightcrawler's, Squirrel Girl's; Chains: Luke Cage's; Wings 1–4: the Angel, Archangel and Wasp team-ups' wings, and Black Bolt's cape webbing with small beats). A hero with its own bones of a kind always keeps them; that kind shows as the hero's own and adds nothing. A coat and a dress (or a cape and wings) hang in the same place: the model's strips pair with whichever is nearer. Remove All takes every added rig off.

Bone Map: which hero bone each of the model's bones drives, and which chain its hair, cape and strap chains ride. Click a hero bone to change it. Smooth Weights softens the selected bone's weights (each click another pass; Undo takes it back); Weights paints the model by how much the selected bones move it (blue none, red all); key W steps through off, the weight colours over the textured model at 50 %, and the weight colours alone; Bones shows the skeleton (key B; Ctrl+click a bone in the preview to pick it here). Reset to Automatic forgets your changes.

Paint (under the filter; key Shift+P) paints the selected bone's weights on the model, as Blender's weight painting: Weights turns on with it (over the model at 50 %; W for the weights alone) and shows the bone, the left mouse button paints, the middle button turns the view (Shift + middle moves it). Brushes: Draw pulls the weight toward Weight, Add and Subtract change it by Weight, Blur evens it out with the vertices around. Hold Shift to blur with any brush and Ctrl to paint the other way (Draw toward 1 − Weight, Add and Subtract swapped). While painting, Ctrl+Shift+click picks the bone under the mouse (Ctrl+click alone paints), and Weights shows only the bone being painted; a chain's row (hair, a cape) has several bones: pick the one to paint in the bone list beside the brushes. [ and ] step to the bone above (the parent) and below (a child) in the skeleton. Strength is how much one dab changes, Radius the circle's size; in the view, F changes the radius and Shift+F the strength as you move the mouse (click to keep, Esc to put it back). The brush reaches every part of the model it touches (a jacket over a shirt), and seams paint as one. Each vertex's weights stay summed to 1: what the bone gains is taken from the vertex's other bones. Mirror paints the other side too (left and right bones swap). Invert Bone turns each weight of the bone into 1 minus it, Smooth Bone smooths it over the whole model, Clear Paint takes all the painting off. Every stroke is one Undo step (Ctrl+Z, Ctrl+Y). The painting is saved with the mod for this model on this target, applied after the fit, so Build, the preview and Open in Blender all use it; if the model's parts or vertices change (Smooth (Subdivide), a mesh edited in Blender), the paint on the parts that changed is dropped and the log says how many vertices.

Materials

Each material's maps and where they come from: Color, Normal, Spec, MHO Spec, Spec Color, Glow and Alpha. A map is the model's own (found beside it, by name: <material>_n, _sp, _mhospec, _speccolor, _glow, _alpha, or named in the FBX), your file, made by the importer (a normal map and a spec map from the color map), or none. Double-click a row to see its map large, made ones too. Preview Shows switches the preview to one map or spec channel at a time. The buttons (point at one for its name):

  • Replace File puts your own image in for the selected map (copied into the mod); Back to Automatic takes it out again.
  • Generate Normal Map (right-click a Color or Normal row) makes the material's normal map from its color map, bright parts raised, and uses it in place of the one it has: Soft, Medium (what the importer makes on its own), Strong, or Medium, Dark Is Raised. With no source picked, it replaces the normal-map texture in the mod's copy of the package. Undo takes it back. Every normal map the tab writes is set up the way the game reads its own (sRGB off, normal-map compression); one read as a color image lights wrong and shows seams across faces.
  • Adjust Colors (on a Color row; also in its right-click menu) changes a material's color map without editing the file: Hue, Saturation and Brightness as on the Powers tab, and Levels (Input Black and White, Gamma, Output Black and White), with the map before and after side by side. The preview, Build and Export FBX use the adjusted map; the values are kept with the material (the button is lit while a map is adjusted), Undo takes a change back, and Back to Automatic on the Color row clears it. Color tags are still matched on the map as it was. Export Maps saves every material's maps, made ones too, under the names the import reads, so they can be edited and used again.
  • Game Material ▾: which of the game's materials the selected material is built from. Automatic picks from the maps (metal maps or an MHO spec map: Metal; a glow map: Glow; else Cloth and Skin), as for the whole model before. Cloth and Skin (Punisher's material), Metal (Angela's armor: its own reflection image and spec color), Glow (Angela's weapon: a glow slot) and The Costume's Own (the target's own material) set it by hand. Each material can have its own, so a model with a body and armor can build the body in cloth and the armor in metal. The game can't make new shaders, so these are copies of materials it already has. The Slot column shows the choice; the preview follows it.
  • Slot (a column; Slot Up / Slot Down): the game material slot each material is built into, 0 first (by default the model's own order). Some costumes' effects name slots by number: Hulk's revive visual paints the skin on every slot but the pants slot, Doctor Doom's force field tells body from cape, Rogue's healing shields and Vision's stealth do the same. For such a costume a line under the buttons says which slots its effects keep; move your materials so the body, pants or cape sit in those slots, and the effect lands right. The build log's slots: lines say the same.
  • OpenGL Normals: for a normal map made the OpenGL way (Blender, Unity, Maya, Substance's OpenGL preset), whose bumps look dented. A normal map the importer makes is already right.
  • Next Recipe steps a made spec map through its recipes: Soft, Strong, Dark Is Shiny, Detail and Flat.
  • MHO Spec is a spec map in the game's own packed form: R shine, G power, B skin mask, A reflectivity (what makes metal look like metal). Layout ▾ says which of the game's six packings a map is in (read from its name when it carries one); others are converted, and a glow channel becomes the material's glow map. From Channels builds one from four gray images: image editors such as Photoshop show a PNG's alpha as transparency and can change the colors under it when saving, so the export writes each MHO spec map as gray _R, _G, _B, _A images too, and newer channel files are read back.
  • Tag Colors makes the spec map from what each color group is made of: Metal, Skin, Leather, Cloth or Glow (values measured on the game's own maps). Point at a group to see where it is; click the picture to find a color's group. The Eyedropper (or a double-click on the picture) makes a color a group of its own, for small details such as eye whites; Reach sets how far a group takes in neighboring shades. The mouse wheel zooms the picture, right-drag moves it.
  • No Glow (on a Glow row) turns a material's glow off.

Size in Game makes the character larger or smaller in game (5–400 % of the game's own size; double-click for 100 %). It's written as the costume's mesh scale, the way the game sizes its own costumes (Spider-Man Homecoming, Wolverine, Carnage …), so the whole posed character is scaled: the animations keep their shape and the feet stay on the ground. The preview shows it; Compare shows the hero at the game's size. It works without a model too: with no source picked, pick the costume package under Target, set the size and click Build into Mod to write only the size (a model built in earlier stays). Sizing again replaces the size; 100 % puts the game's back. Feet moves the whole model up or down in game (units): the game's animations hold the hips at the stock hero's height and the legs hang from there, so a model with shorter legs would hover and one with longer legs would sink into the floor. The slider starts at the automatic amount for the model and target (marked Auto: the model's lowest point in the hero's idle, moved to the floor); move it if the feet still float or sink in an animation (a very different body: Hulk on Black Widow), double-click to go back to automatic. The preview shows it; Build writes it (the log says how far). Lean (under Feet) turns an MFF model above its feet at the ankles, in degrees (+ forward, − back; the soles stay flat), for a model that stands tipped forward or back in the hero's animations; double-click for 0. An MFF model is fitted to the target's height by default (Hulk on Black Widow comes out her height); Keep the Source's Size keeps its own size against the other MFF characters instead (Hulk stays Hulk-sized on any hero), and Size in Game and Feet start from there. Match Steps to Size (on by default) keeps the feet from sliding: the game moves a character at the same speed whatever its size, so the costume's run, walk and other movement animations play slower for a bigger character and faster for a smaller one (at 1 / size; landings and jumps keep their timing). Only this costume's animations change: they're copied into its own package, as the Animations tab does. Game Joint Blend (a test feature, off by default) shares the skin around the hips, knees, shoulders and elbows between the limb and the body the way the target's own game model does, over a wide band, instead of the MFF model's narrow handover: the seat stops creasing and the shoulders and thighs bulge less when the hero moves, and the pelvis turns where the game's does. Compare it in the preview (Look ▾ → Weights shows the result), then in game.

Material picks the game material the model is built with: Automatic (from the maps: Angela's armor material for metal and MHO spec maps, her weapon material when something glows, else Punisher's cloth), or one of them by hand.

Preview, Build and Blender

The preview works like the others (P plays, Esc pauses, Look, framing, full screen). Compare shows the hero's own model in the same pose. Single Animation ▾ exports just the picked animation, or brings back edits made to it in Blender.

Build into Mod puts the model into the picked package (and onto any other model the character swaps to: Ant-Man's shrunk model, fitted to its own size); Save Changes keeps it and Apply Changes puts it in the game like any other package of the mod. A change the build hasn't put in yet (a new source, parts, materials, the bone map, the size, a Blender edit) is not lost silently: leaving the Model tab asks Build Now, Stay on Model or Leave It Unbuilt, and Save Changes asks Build and Save, Save Without Building or Cancel. Full Export ▾ writes the model and all the hero's animations as FBX files (Export FBX), or opens them in a new Blender scene (Open in Blender). In that scene, every Ctrl+S sends what you changed (the mesh, its weights, bones moved in Edit Mode, the animations whose keys changed) back to the tab, from a Single Animation scene too; a moved bone keeps its orientation and only its joint moves; the status line turns green, and the next build uses it. On the Materials tab, double-click a row to see its map large (zoom, Export as PNG, and Edit in your image editor, or E), or right-click it for View Large, Edit in Image Editor, Replace File, Generate Normal Map and Back to Automatic. Ctrl+click the model in the preview to select the material under the mouse (a model with several materials). With no source picked, the tab lists the shown package's own textures (a model built into the mod earlier, or the game's): Edit in Image Editor, Replace File and Adjust Colors (Color rows) change them right in the mod's copy of the package, encoded like the original (DXT1 or DXT5, its size, with mipmaps); an adjusted texture is the texture itself from then on, so adjusting again starts from it. Edit in Image Editor (Materials tab, the pencil) opens the selected map in your image editor: GIMP, Photoshop, Corel PHOTO-PAINT, Affinity Photo, Krita or Paint.NET are found when installed, or pick any program in Settings → Model → Choose Image Editor. It's a PNG copy in the mod's Model folder; every save there comes back into the tab as that map, like Replace File (keep its name and PNG format: in GIMP, export with Ctrl+E; Ctrl+S only saves GIMP's own .xcf, which the app doesn't see). Texture Paint in Blender works the same way: Ctrl+S also saves the painted images (in a scene opened before 0.37.178, save the image itself with Image → Save), and each painted texture comes into the Materials tab as that material's map (color, normal, spec, glow …, by its file name), the same as Replace File; the 3D view shows it, the next build uses it, and Back to Automatic undoes it. Settings → Model sets the MFF folder (Change MFF Folder: your rip's top folder; its models can be in Models\Models, Models or right in it, its textures in Texture2D, Texture2D\Texture2D or Textures, all found), sets the folder Browse for a Model opens in (Change Models Folder; not set, it opens where you last picked a model), chooses the Blender and the image editor, installs the optional MHO Actions add-on, opens the exports folder, and Clean Up Exports and Rigs lists old exports and rigs to delete. Undo and Redo (Ctrl+Z / Ctrl+Y) cover the parts, the bone map, the material and the Materials tab. The ⛶ in the log's top right corner shows the log full screen (it keeps filling during a build); Esc or ⛶ come back.

The tab's work (your choices, bone map changes, material files, the rig and FBX edits, and the package as it was before the model) is kept in the mod's Model folder, so editing the mod later continues where you left off. A full export carries it along; a legacy export leaves it out. Only the game's existing packages change, and only through Apply Changes; nothing on the server changes.

Voice Lines

The Editor's Audio → Voice tab lists the voice set of the mod's costume packages: the Situation (Death, Level Up, Crit Hit Landed, Banter …), extra Detail (the enemy type or mission) and the Sound Event it plays. Only costumes with their own voice set have lines here: a voice mod, or a costume moved to another hero (which brings its voice along). For any other costume, Use Another Voice (or the hero's-voice button the tab offers) puts a voice in first.

To shift a voice (for example a female voice to male):

  1. Open the mod in the Editor and go to Audio → Voice. If no lines show, use the button above the list (or Use Another Voice) to put the hero's voice in.
  2. Click Female → Male or Male → Female as a start, then adjust Pitch, Formant and Warmth. Press ▶ on a few lines to hear the result; nothing changes in the mod yet.
  3. Click Apply to This Voice (about 30 seconds), then Save Changes.
  4. Turn the mod on and Apply Changes; the costume speaks with the shifted voice in game.
  • ▶ plays a line: from the mod's own sound pack if it has that line, otherwise from the game's sound files. Stop stops it. If a line has no sound anywhere, it says so; it's silent in the game too.
  • Untick a line to turn it off, for example when a voice borrowed from another hero names its own team. Save Changes writes it into the mod's package; the mod remembers what was turned off, so it can be ticked again later (or Turn All On).
  • Find narrows the list by words in the situation, detail or event.
  • Use Another Voice gives the costume a whole voice from the game. Its hero's own voice comes first: a stock costume has no voice set of its own (it uses its hero's), so this is how you get its lines to play and turn off. Below it are the other voices the game has, such as Lady Deadpool, Spider-Gwen or Jane Foster, and under Other Heroes every hero's voice. The costume's powers then play that voice's lines. Back to This Mod's Voice undoes it before you save.
  • Some entries aren't sounds: a Banter Target names a character other heroes' banter is about, and some emotes name an animation. They have no ▶ and aren't shifted.
  • If the mod's packages have no voice lines, a line above the list says where the hero's voice is in the game. Some heroes keep it outside their main package: Carnage's comes from his Classic costume, which plays the Carnage voice package. Add Classic and Use Its Voice adds that costume's package to the mod (the game's copy) with the voice put in, so it can be played, turned off and shifted. When the mod is for one of the hero's other costumes (White Tiger on Iron Fist Classic), the button is Use plus the voice's name instead: the voice goes into that costume's own package, so the shift reaches the costume the mod changes.
  • Voice Shift makes the voice higher or lower, for example to turn a female voice male or the other way round. Pitch moves the voice in semitones, Formant moves the size of the throat you hear (lower sounds bigger), and Warmth adds body (a raised voice can sound thin). Female → Male and Male → Female are starting points; Original sets everything back to 0. While you move the sliders, ▶ plays the original line at those settings. Apply to This Voice shifts every line that is on (about 30 seconds) and Save Changes puts it into the mod; the line next to the buttons shows the saved settings, and ▶ then plays the lines as the mod has them. Remove Shift brings the original lines back.
  • Effects (the row under Voice Shift) filter the voice, each from Off to 100 %: Reverb (a room, up to a hall), Echo (repeats every quarter second), Distortion (gritty to heavily clipped), Lo-Fi (radio or old speaker: a narrow band, fewer bits), Chorus (doubled, wavering) and Robot (metallic ring modulation). They combine with each other and with the shift; ▶ previews them, and Apply to This Voice puts them in with the shift. Reverb and echo let a line ring out up to about a second longer. No Effects turns them all off. Like the shift, the result is a sound pack MHModManager can install too.
  • Only the costume's voice lines are shifted. Sound effects in its voice set (such as a dodge), the hero's other costumes and every other character keep their sounds. The shift goes into the mod as a sound pack, so the old MHModManager installs it too. Use Another Voice drops a shift: shift the new voice again if you want it.

Icons and Create from 3D

In the icon, store and portrait tabs, Create from 3D makes the image from the character itself: frame it (drag, pan, zoom), pick a pose and frame from the animations, a lens and the light, Spec / Reflect / Glow / Effects (shared with the main preview; the snapshot is taken as shown; Effects adds the character's own glows and flames, such as Ghost Rider's burning head, run for a few seconds on the pose so they're fully grown; on a transparent background their light keeps its color with see-through edges), show the weapon or prop, and lay the game's original over it to line things up (O). Thirds, Center and Safe Area draw framing guides over the view (rule-of-thirds lines, a center cross, a dashed frame 8 % inside each edge); they're never in the snapshot. Characters start facing the camera; the Turn slider turns them (0° = straight on), and Reset View goes back to the usual framing, facing front, with the standard lens and light. The snapshot is made at the original's exact size (the game only takes that size). For a post or promo shot, Save Large PNG ▾ saves the framed view at 1024 or 2048 pixels, square (more room at the sides) or in the icon's shape, on the same background; it stays out of the mod. Each icon remembers its setup; Use Previous Setup copies the last one.

Click the Original, Replacement or Snapshot picture to look closer: fit, 1:1, zoom, full screen (F11) and save as PNG (Ctrl+S).

Extract

Extract (the picture icon beside Install Mod in the top bar) saves the game's own images (as .dds or .png) and strings (as a language .json in the mod format), always from the clean originals, never from files mods have changed.

Nexus

The strip above the mod list links your mods to their Nexus pages and checks for updates, using Nexus's public data (no account needed). Signing in (optional) adds one-click updates for Premium members.

  • Find My Mods matches your mods against the game's Nexus mods and lists likely pages; tick the right ones and link them. Mods installed from a Nexus download are linked by the file's name automatically.
  • Check for Updates looks at every linked mod; mods with a newer version get the green ↑. Click it to open the Files page; download the file and the app offers to install it as the update.
  • A Nexus page with several files (a default and a variant): right-click → Nexus → Choose the Nexus File says which one your mod follows.
  • Sign In with Nexus (the strip's ▾): your browser opens Nexus to approve the app; the app never sees your password, and keeps the sign-in encrypted for your Windows account in its data folder. With a Premium account, ↑ UPDATE downloads and installs the new version in one click (card menu → Download From the Files Page Instead does it the manual way). Sign Out removes the sign-in here and at Nexus.

The Data Folder

Everything the app keeps is in data next to the program. Each normal start clears what nothing needs any more, so you don't have to:

  • converted: images converted for the editor (PNG to DDS, Create from 3D snapshots). Save copies them into the mod, so the copies here aren't needed after the app closes.
  • downloads: mods downloaded from Nexus for a one-click update, once installed. update: an app update that stopped part way.
  • model\converted: the FBX copies Blender made of .blend and XPS models, once their file is gone or they haven't been used for 30 days and aren't in the model list (made again when picked).
  • model\inherit: the Model tab's copies of costumes with their hero's model in them (made again when needed).
  • model\thumbs: thumbnails of model files that no longer exist, and any not shown for 30 days (made again when needed).
  • The editor's work folders in library (model-work-…, power-colors-…, voice-…, anim-work-…, costume-move-…) that a closed or crashed run left.

Keep the rest: library (your mods, the game's clean originals the app restores from, its list), settings.json, and history (a small record of each game file the app wrote, so Apply can tell its own changes from other programs'; no copies of files any more). model\fbx and model\rigs hold your Model-tab exports, Blender scenes and rigs: clear them with Settings → Model → Clean Up Exports and Rigs, which shows what each one is and sends the ones you pick to the Recycle Bin. model\converted holds Blender and XPS models read through Blender; it's made again when you browse to them.
