MHO Extended Mod Manager: what's new
====================================

0.60.209
- Model tab, Props: a prop shown with a left click has its texture the right way up (it was flipped).

0.60.208
- Model tab: right-click a target → Revert to Original: the costume back as it was before the Model tab built onto it (the mod's own copy from before, else the game's), its added props off and the source cleared, so the preview shows the costume itself.

0.60.207
- Model tab, Props: a left click on a prop in the list shows it on its own over the preview (Back to the Costume or Esc returns); a right-click adds it to the target.
- Model tab: right-click a target → Revert to Last Build: the package back as its last build made it, with the props as they were then (props added, fitted or moved since are dropped).

0.60.206
- Model tab: adding a prop works on a costume that uses its hero's prop list (Doctor Doom Classic said "this costume has no prop list of its own"): the costume gets a list of its own, the hero's props (Doom's pistol and throne) plus the new one, referenced as the game's own costumes do.

0.60.205
- Model tab: a Props tab between Characters and Effects, in place of the Add a Prop ▾ button. Pick a character on the left (From the Game, an MFF character or a Single Model FBX): its props are listed under it (a costume's props, an MFF character's parts with its weapons first, an FBX as made), and a click on one adds it to the costume picked under Target. From the Game also lists a costume's animated props (Squirrel Girl's surf squirrels) and its summons and power models (her squirrels), each added as a model of its own. A click on a character there never changes the target or the Characters tab's source; characters are changed only in the Characters tab.

0.60.203
- Model tab: an MFF part as a prop (Add a Prop ▾ → From the Source's Parts, or right-click a part → Add as a Prop): an MFF weapon goes on the costume as a prop of its own, sized to the hero. MFF parks a hand's weapon beside the character in its rest pose (Red She-Hulk's 131 cm away), so it's put on that hand, its turn kept (the Prop Fit sliders turn it); one worn on the body (a holstered gun) stays where it's worn. Its bone, fit and paint as any added prop.

0.60.202
- Settings → File Pickers → Model Pickers: a view of its own for pickers of 3D models (.FBX, .OBJ, .BLEND …), Last Used by default, so models can be browsed by their thumbnails while packages stay in Details.

0.60.201
- Settings → File Pickers: choose the view the Open and Save windows start in, one for package (and other) pickers, one for image pickers: Details, List, Small / Medium / Large / Extra Large Icons, Tiles, Content, or Last Used. Image pickers start in the view you last left one in (they always went back to Details).

0.60.200
- Model tab: right-click → Remove (first in the menu) also on the costume's own props: it leaves the game's prop off this costume (Put Back brings it back); Del does the same. Leave Off for Now (an added prop, its settings kept) is further down.

0.60.199
- Model tab: The Target's Props has a right-click menu (an added prop: Pick as Target, Leave Off / Put Back, Remove; the costume's own: Leave Off / Keep), and Del removes the selected added prop (Ctrl+Z brings it back).

0.60.198
- Model tab: Undo / Redo (Ctrl+Z / Ctrl+Y) take back prop changes too: adding, removing, ticking an added prop, its Prop Fit, and Held On (the costume's own props' too). A removed prop comes back with its fit, bone and model.

0.60.197
- Model tab: unticking an added prop in The Target's Props leaves it off the costume (its fit, bone and model kept); ticking it puts it back as it was. Remove still takes it away.

0.60.196
- Model tab: more room in the right column. The build's game material (Material ▾) moved to the Materials tab, beside Preview Shows, as Game Material. The Parts tab is one list: SOURCE PARTS, then THE TARGET'S PROPS, each as tall as its rows (the list scrolls), with Add a Prop ▾ and Remove in its toolbar.

0.60.195
- Model tab: Add a Prop ▾ → From an FBX gives a costume a prop of your own. Pick the FBX: a plain prop class from the game (one the costume doesn't have) carries it, and its model is built as made (its size and shape kept, its origin on the bone; an FBX without bones is held rigidly). Then Held On ▾ puts it on the bone you want and Prop Fit fits it. Add a Prop ▾ → From a Character is the earlier Add a Prop.

0.60.194
- Editor: its working copies of a package keep the package's own file name (in a folder each). After an added prop, a prop's bone, an animation or voice change, a Model tab build read a renamed copy: the costume's Size in Game was left as the game's ("no …initialskeletalmesh in 037aa2_UC__…") and the built file took the odd name.

0.60.193
- Model tab: a build that keeps another model built in the package (it starts from the mod's copy) cleans up after the earlier builds: their textures nothing uses any more are made 4×4, so the package stops growing (Thor Age of Ultron's had gone from 6.5 to 30 MB; cleaned, 8.8 MB). Every texture a model uses stays as it is. Build the package once more to clean one that has grown.

0.60.192
- Model tab: a prop built again after the character's body is laid over the game's prop, as the preview shows it, not over the last build of it (Captain America's shield came out 3× too big and turned, laid over an earlier 176 % hammer).
- After an added prop or a prop's bone went into a package, a build or the no-source preview of one of its props read the character's body instead (a build of the hammer went onto Thor's body; the hammer's preview showed nothing). The editor's working copy now counts as the package.

0.60.191
- Model tab: a prop's Held On ▾ and fit show in the preview at once while that prop is the target (the hammer moved to the left hand only after stepping to another model).

0.60.190
- Model tab: Held On ▾ under Prop Fit puts a prop on another of the character's bones (Thor's hammer in his left hand, a weapon on the back or hip), for the costume's own props and the added ones. The hands come first in the list; Held On: Its Own puts it back. It goes into the package at once (only this costume's), building the character again keeps it, and the Prop Fit sliders then fit it on that bone.

0.60.189
- Model tab: building a character's body after one of its props (Thor Age of Ultron's hammer) keeps the prop as built. The body's build started from the game's package, so the hammer went back to the game's.
- A character's own model as the source (From the Game) no longer glows all over. A packed spec map stored without alpha (DXT1, Thor Age of Ultron's) read its missing alpha as glow everywhere, so the rebuilt body was its colors at glow strength (too bright in the preview and in the game). Build the body again for the fix.

0.60.188
- Model tab: stepping from a prop to an added prop no longer carries the prop's source over (the hammer's model showed in place of Angela's axe). A model of the same package (the character's body, another prop's own model) is never another target's source, saved or not; a target with no source of its own shows its own model.

0.60.187
- Model tab: an added prop can get a new model. Picked with ◀ ▶, it's the build's target: pick a source (an MFF part, an FBX, or a model from the game) and Build into Mod lays it over the prop, as for the game's own props, and puts it into the costume with the prop's fit. The preview shows it in the hand with that fit, and Paint works on it. With no source, Build into Mod puts its character's own model back (it asks first). The new model is kept in the mod's Model folder, so rebuilding the character keeps it.
- A prop picked as the target no longer takes the character's own body as its source (the body was fitted onto the prop).
- A removed added prop no longer stays the target.

0.60.186
- Model tab: props from other characters are added, removed and fitted here. Add a Prop and Remove are beside The Target's Props (under Parts), which lists the added props too. An added prop is in the ◀ ▶ selector under the preview ("Angela: Angelaaxe left · Added Prop"); picked, its fit is on the Prop Fit sliders and goes into the package when you let go of a slider. The character stays the build's target.
- Animations tab: the Props section keeps how added props move (Pivot on the Hand, In This Animation), with a button to the Model tab for the rest.
- Fixed: a build and an added prop going back in at the same time could mix up their messages, so a refusal could lose its reason.

0.60.185
- Model tab: a prop added on the Animations tab (Angela's axe on Thor) stays in the preview with the character as the target, not only with a prop as the target. The preview reads the props from the mod's own copy of the package.
- A Model tab build now puts the Animations tab's added props back into the package right away, also when the package has no animation changes or borrowed powers. Before, they came back only on Save.

0.60.184
- Model tab: the model a package's build replaces (its character or one of its props) is picked under the preview with ◀ ▶, as in the Mods tab's 3D view, in place of Model ▾ above the Target list. It reads like "hammer · Prop (2 of 2)"; click the name for the whole list (with Automatic).

0.60.183
- Model tab: the character and its prop show together whichever one is the target. A prop target is held by the character as you last fitted it (else as built into the mod), and Paint and Weights work on the prop right there in the hand, no longer on its own. The character as the target holds the prop as you last fitted it (else as built into the mod), so switching Model ▾ between them keeps both in place.

0.60.182
- Model tab: each model in a package keeps its own source. Model ▾ back from a prop to the character puts the character's source back (the prop stayed the source before: no preview and nothing to paint); a character with no source of its own takes its own model from the game.
- Paint with no source picked (the target's own model shown) makes that model the source first, so the game's own character can be repainted; Build into Mod writes it with the paint.

0.60.181
- Animations tab, Add a Prop: a prop its own hero shows only while a power calls for it (Angela's axes) is now held all the time by the costume it's added to; it never showed before. A prop added earlier is fixed the next time it's refit or saved.
- Model tab: Paint and Weights on a prop target show the prop on its own (the model being painted); off, it's back in the character's hand. To paint the character, pick its body in Model ▾.

0.60.180
- Model tab: a prop is previewed in its character's hand (Thor holding the hammer), posed by the character's animations and powers, so Prop Fit can be judged where it matters. Compare shows the game's prop in the hand instead. The prop shows even with Props off in Look ▾.

0.60.179
- Model tab: Prop Fit. While the target is a prop (Thor's hammer), the Size in Game sliders become Move X / Y / Z, Turn X / Y / Z and Size, so another model can be lined up with the game's grip in the app: turned and sized around the bone the prop is held on, then moved. The preview follows at once, Build into Mod applies it, and each prop keeps its own fit. Reset Fit puts them all back; double-click a slider for one.

0.60.178
- Model tab: props in the Source's panel under From the Game → Heroes (with the summons): the picked costume's props (Thor Marvel NOW: Prop: Hammer; a hero's row: all of the hero's), 227 prop models. A click makes a prop the source; a right-click the source and the target (its package added to the mod, the build pointed at it), to change it in Blender or to put another model on it.
- A prop can be built from an FBX or a game model now (it was MFF parts only): laid over the game's prop by its shape. Its own model, edited in Blender, comes back exactly as edited. A prop's model is never guessed as a body or rigged in Blender.
- Build into Mod puts a prop into every package of the hero with the same model; other characters' copies (Skrull Thor, the team-ups) are asked about.
- The preview frames a model afresh when it's of quite another size (a hammer after a body showed as a dot).
- --prop-census, --prop-fbx-probe, --model-props-test.

0.60.176
- Model tab summons: when a power shows one model and summons another (Strike Team - Beast tumbles in as the power's own Beast, then stays as the summoned Ultimate Beast; Strike Team - Jean, Call Kurt, Fastball Special, Wrath of Bast), a Build into Mod onto one offers the other: Build onto It Too builds the same source onto it (added to the mod when needed). A power that summons several characters (To Me, My X-Men!) isn't paired.
- --summon-partners lists the pairs; --mesh-info lists a package's skeletal meshes with vertex and bone counts; --model-partner-test tests the offer.

0.60.163
- Discarded copies instead of the Recycle Bin: when a mod's folder is replaced (an edit, Make Unique, Fix Mirror Tables, an update, a bundle) or removed, the old folder is kept in data\library\discarded (moved: instant). Kept 30 days by default (Settings → Snapshots: 7, 30, 90 days or until cleaned up), deleted at a start after that; copies a saved snapshot still needs are only deleted after a warning (Keep Them / Delete Them). Clean Up Discarded deletes them by hand, keeping the ones snapshots need if you like.
- Restoring a snapshot now puts the mods' files back too: removed mods come back, edits, updates, Make Unique and Fix Mirror Tables are undone, Keep Shared Paths goes back. Without a kept copy, Make Unique is undone from the mod's own copy, or only Keep Shared Paths is set back. The preview lists every mod whose files change.
- The Snapshots window's buttons are icons (names in the tooltips); Restore sits beside Take Snapshot; the discarded copies' count and size show at the bottom.

0.60.161
- Settings → Snapshots: the library's state at points in time, taken at every start (kept), before every Apply (the last 30 kept) and by hand (Take Snapshot, kept). A few KB each: mods on/off, order, locks, tags, notes, each mod's version, install date and files, Make Unique / Keep Shared Paths, the OVERLAP and CRASH RISK warnings, what was done to each mod (installs, updates, Fix Mirror Tables, Make Unique for Overlap or Crash Risk …), and the game files Apply wrote.
- Compare with Now / Compare Two: what changed (mods installed, removed, turned on or off, moved, updated, made unique, warnings, fixes done in between, game files written). Restore puts a snapshot's state back after a preview (Undo takes it back).
- Bundles: Make Bundle saves the mods themselves with their state in one .zip (ask each time, every mod, or the turned-on ones: a setting in the window); Restore Bundle installs what's missing, replaces what differs if you say so, and puts its state back.
